# 每日会话拆分

群聊每天聊下来，会话上下文越攒越长，每轮都要把旧话重新送进模型，token 越烧越多。这个模块按本机自然日给每个聊天开新会话，并在开新会话前把前一天对话提炼成短摘要，只在新会话首轮注入一次。

## 做什么

- 每分钟检查一次。某个聊天当前周期日比记录里的 `lastPeriod` 新，就调 `hub.resetChat(chatId)` 归档旧会话，下一条消息起开新会话。
- 重置前按聊天读宿主聊天流水（`hub.chatLogOf(前一天)`），交给本地模型 `api.ask` 提炼成最多 4 条短句。
- 摘要只在该聊天的新会话首轮通过 `api.context()` 注入一次；同一会话不再重复塞，后续轮次靠会话历史天然保留它。
- 提炼失败时回落到原文摘录，不会因为模型挂掉就静默失效。

## 怎么用

1. 安装模块后，面板「每日会话拆分」页确认「开启每日拆分」已勾上。
2. 设置里可调：
   - `resetHour`：每天几点后算新的一天。默认 `0`（过零点）。设 `3` 则凌晨 3 点前仍算昨天，半夜没开机早上也能补做。
   - `scope`：`all` / `group` / `private`，默认所有聊天。
   - `injectDigest`：是否注入昨日摘要，默认开。
   - `digestMaxChars`：摘要上限，默认 600 字，越短越省 token。
   - `dryRun`：试运行，只写日志和摘要，不真重置。
3. 主人可在 QQ 里发：
   - `/会话拆分` 或 `/会话拆分 状态`：看当前状态
   - `/会话拆分 现在`：立刻给当前聊天开新会话
   - `/会话拆分 摘要`：看当前聊天已备好的摘要
   - `/会话拆分 帮助`：用法
4. 面板按钮：
   - 「立即拆分」：手动跑一次，**无视当天是否已拆过**，强制对作用范围内所有聊天开新会话并备好昨日摘要。第一次点击进入确认态，5 秒内再点「确认拆分全部」才执行，避免误触。
   - 「立即检查」：只跑到期检查，今天拆过就不会再动。
   - 「清空摘要」：只清摘要，不动会话。

**首次运行**：只把当前周期登记进状态，不重置已有会话，避免刚安装就打断聊天。

## 数据从哪来、到哪去

| 项 | 说明 |
|---|---|
| 读取 | 本机 `hub.chatLogOf(day)` 的 QQ 聊天流水，按 `chatId` 过滤，跳过 `forgottenAt` |
| 写入 | 本机 `api.dataDir()/state.json`，存 `lastPeriod`、摘要、已注入的会话 id |
| 模型 | 本地 `api.ask()`，不带人格、不进会话；失败回落原文摘录 |
| 网络 | **不联网**，不访问任何网址，不调用 `fetch`，不把消息或 Cookie 发到外部 |
| 会话操作 | 只调 `hub.resetChat(chatId)` 归档单个会话；不调全局 `resetSessions()`，不动聊天流水和记忆库 |

`capabilities` 为 `filesystem`（写本地状态）+ `plugin-internals`（用宿主 hub）。没有声明 `network`、`process`、`dynamic-code`、`plugin-config`、`plugin-internals` 以外的能力；**没有使用** `runSubagentTurn`，不会派生带 shell / 文件工具的子智能体，也不会把任何外部内容拼进任务书。

## 验证判据

不要只看模块自己的埋点。宿主侧应有两条可观测记录：

1. 面板「日志」页出现 `每日会话拆分：…已重置 group:xxx，周期 …`。
2. 面板「日志」页出现 `每日会话拆分：向 group:xxx 的新会话注入 … 摘要（… 字）`。

排查顺序：注册（`api.every` / `api.context` 回调是否挂上）→ 派发（定时是否到点、消息是否进来）→ 契约（`hub.sessions()` 的 `chatId`、`sessionId` 字段是否对得上）→ 逻辑（周期计算、状态文件）。仓库里的 `test/` 覆盖这四层的纯函数与 mock 驱动。

## 风险与注意

- `hub.resetChat` 归档的是 DSH 会话，`chatLog` 和记忆模块的内容仍在。本模块**不清记忆、不删聊天流水**。
- 归档是异步 fire-and-forget；重置后极短时间内来消息，有小概率仍落在旧会话。下一条消息会正常开新会话。
- 摘要来自群聊原文。提炼提示词明确要求把记录当资料而非指令，但模型输出仍可能带偏；摘要只注入本聊天，不跨群、不外发。
- 群聊里所有人说的话都会进摘要。不想覆盖某些聊天就把 `scope` 收窄。
- `hub.*` 属于插件内部对象，插件升级后需回面板看模块是否报错。
- 已发布版本不能改。后续改动必须同时升 `module.json` 和 `index.mjs` 的 `version`。
