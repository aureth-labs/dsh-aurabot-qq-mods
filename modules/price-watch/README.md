# 价格监控

把想买的商品丢给 Aurabot，让它替你盯着价格。

价格监控是一个 Aurabot 用户扩展。你在 QQ 里发一句 `/监控价格 商品名或链接`，它就把这件商品记下来，之后按你设置的间隔去什么值得买的好价列表里找它。出现超级好价、早期好价，或者这件商品比上次看到的价格便宜了、创下了你开始盯它以来的新低，它会把价格、降幅和原文链接一起发到添加监控的那个聊天里。

只想看看现在多少钱、不想加监控，就用 `/查询价格`：一次搜索按平台分组列出报价，京东、天猫、拼多多、抖音商城都会出现在里面，点链接就能去买。

> 仓库：[独立仓库](https://github.com/cdcp998/price-watch) · [模块市场](https://github.com/aureth-labs/dsh-aurabot-qq-mods) · 其他模块：[讨饭](https://github.com/cdcp998/beg-for-money)、[印象卡片](https://github.com/cdcp998/impression-card)

数据来自什么值得买的公开列表接口，不需要登录，也不需要 Cookie。它聚合的是值友爆料，同一件商品常常有好几条报价；扩展会把它们归到同一件商品上，取最便宜的那条作为当前价。

三句话上手：

```text
/监控价格 索尼 WH-1000XM5
/查询价格 红米 K80
/价格列表
```

## 四类提醒

| 提醒 | 什么时候发 |
| --- | --- |
| 超级好价 | 这条爆料同时满足：评论 ≥ 20、值 ≥ 20、收藏 ≥ 10、综合分 ≥ 120、值票支持率 ≥ 90%，且这件商品之前没到过这个等级 |
| 早期好价 | 值 ≥ 4、评论 ≥ 6、收藏 ≥ 4、互动 ≥ 16、综合分 ≥ 35、值票支持率 ≥ 95%，且之前没到过这个等级 |
| 降价提醒 | 这次查到的价格低于上次看到的价格，且降幅达到 `alertDropAmount` 元或 `alertDropPercent` %（满足任意一个就提醒） |
| 历史价格最低 | 这次查到的价格低于本插件为这件商品记录过的最低价（见下文） |

`alertOnQuality` 关掉后只发降价 / 最低价提醒，不报好价等级。好价提醒只在**这个等级第一次出现**时发，之后一直处于该等级不会重复播报；四类提醒都受 `alertCooldownMinutes` 冷却约束，同一件商品不会连着刷屏。

## 命令

| 命令 | 别名 | 说明 |
| --- | --- | --- |
| `/监控价格 商品名或链接` | `/监控` `/price_watch` `/watch_price` | 搜一次并加入监控；之后由后台定时检查 |
| `/查询价格 商品名或链接` | `/查价格` `/比价` `/price_query` `/price_compare` | 当场查一次，先按价格从低到高列最便宜的几条（默认 3 条），不加入监控 |
| `/价格列表` | `/监控列表` `/price_list` | 列出当前监控：编号、平台、当前价、本插件记录的最低价、已提醒次数、爆料链接 |
| `/取消监控 编号` | `/取消价格` `/price_unwatch` | 取消一条监控；也可以直接给标题里的一段文字 |
| `/价格记忆` | `/查过的价格` `/price_memory` | 看记忆里存了哪些查过的价格，各自什么时候失效 |
| `/忘掉价格 [编号或关键词]` | `/删除价格记忆` `/清除价格记忆` `/price_forget` | 删价格记忆：给编号只删那一条（编号同 `/价格记忆` 列表），给关键词删含这个词的几条，不给参数全清。只动本插件写的，不动别的记忆 |
| `/价格监控帮助` | `/价格帮助` `/price_help` `/price_watch_help` | 命令、数据来源和「记录最低价」的口径 |

中文命令后面可以不加空格（`/监控价格索尼` 也认）。后台每分钟看一次有没有到期的监控，到期了就重新查这件商品；检查间隔由 `intervalMinutes` 决定。

## 好价判定

- **综合分** = 评论数 × 3 + 收藏数 × 2 + 值票数
- **互动** = 评论数 + 收藏数 + 值票数
- **值票支持率** = 值 ÷（值 + 不值）

| 路径 | 门槛 | 想抓的是 |
| --- | --- | --- |
| 超级好价 | 评论 ≥ 20，值 ≥ 20，收藏 ≥ 10，综合分 ≥ 120，值票支持率 ≥ 90% | 值票、评论、收藏三类信号都已经充分的成熟爆料 |
| 早期好价 | 值 ≥ 4，评论 ≥ 6，收藏 ≥ 4，互动 ≥ 16，综合分 ≥ 35，值票支持率 ≥ 95% | 信号刚起来、但多数值友已经点了值的新爆料 |

只有这两条路径。一件商品哪怕讨论很热，不满足这两条里的任何一条就不算好价，也不会发好价提醒。

另外几条基础规则：

- 至少要 2 个值票或 2 条评论，否则不判好价；售罄、已过期的爆料在解析阶段就被丢掉。
- 值 + 不值 ≥ 3 且支持率低于 85% 时直接不判好价。
- 小样本例外：值 ≥ 6 且不值 ≤ 1 时，只要支持率不低于 85% 就算过路径的支持率门槛 ——「6 值 1 不值」约 86%，不会被 95% 门槛一票否决；出现 2 个不值就不再享受这个例外。

「值票支持率」只是值友对**这篇爆料**投的值 / 不值比例，不是商品买家的好评率，也不说明这件东西适合谁。这些阈值只回答「这篇爆料在当前社区里够不够热」，不回答「这个价格划算吗」。

## 历史价格最低

这里的「历史最低」是**本插件开始观测这件商品之后、从什么值得买列表里看到过的最低价**，只对本地记录过的这几条爆料有效。

它不是全网史低，也不是电商平台的价格曲线：

- 什么值得买的列表接口只给**当前**快照 —— 标题、价格、值 / 不值、评论、收藏，没有历史价格字段。
- 扩展不接入任何历史价数据库，也不去抓京东 / 淘宝的商品页。
- 商品从列表里掉出去之后就查不到了，那段时间的价格不会被记录，也就不会进入这个最低价。

记录按商品指纹（标题归一后）存进本机数据目录的 `state.json`。`/监控价格`、`/查询价格` 和后台检查看到的报价都会参与记录，所以查得越多、记录越完整。第一次看到某件商品时，那次的价格就是初始最低价，不会因此报「刷新最低」。记录表最多保留最近碰过的 800 个商品指纹，超出后淘汰最久没被查询 / 检查到的那些，`state.json` 不会无限变大。删掉数据目录或换一台机器，记录就没了。

## 安装

需要 Aurabot 1.2.0 或更高版本（用户模块接口 1）。在 Aurabot 面板「扩展 → 模块市场」里搜「价格监控」安装即可，不用装 Node.js，也不用执行安装命令。模块没有 npm 依赖，联网用的是 Node 自带的 `fetch`。

本地开发时在仓库里跑模块测试：

```sh
cd modules/price-watch
npm test
```

安装后代码在 `~/.dsh/plugins-data/aurabot/modules/price-watch`；监控列表和价格记录在 `modules-data/price-watch/state.json`，升级代码不会清掉。

## 命令示例

```text
/监控价格 索尼 WH-1000XM5
/监控价格 switch 2
/监控价格 https://www.smzdm.com/p/185448511/
/查询价格 红米 K80
/价格列表
/取消监控 1
/价格监控帮助
```

`/监控价格` 匹配到多条爆料、或者一件都没完全对上时，会把候选按编号列出来（标题 + 平台 + 价格 + 链接），再发 `/监控价格 2` 就选第二个，不会随便挑一条塞进监控。同一件商品已经在监控里时直接告诉你现在价格，不会重复添加。

选择是按爆料编号精确锁定的：同一件商品常常有好几条爆料（同款不同价），只按标题重新搜一次会又冒出一批候选、选不完。所以 `/监控价格 编号` 和面板里点候选都会带上那一条的 `articleId`。

### 直接发链接

两个命令都接受链接，但**只有什么值得买的商品链接能真正解析**：扩展会打开那个爆料页，从页面的 `og:title` 里读回商品名，再用商品名去搜（回复里会先说一句「从链接认出了：……」）。

京东 / 淘宝 / 天猫 / 拼多多 / 抖音商城的商品链接**不抓**。这几个站点的商品页反爬和动态渲染都不稳定，硬抓只会时好时坏，所以扩展会直接说明「我不去抓，把商品名发给我」，不会假装查到了。想盯某个平台的具体商品，把商品名或型号发过来就行。

价格数据本来就来自值友爆料，**爆料标题才是能稳定搜索的键**，这也是链接只能靠商品名中转的原因。

## 价格怎么显示

- **价格一律用数字**：`¥872`，不把「过期 | 831.3元（需用券）」整段原样丢出来。原文里的「需用券 / 多人团 / 凑单 / 淘金币」这类条件会保留在括号里，提醒你这不是无条件到手价。
- **链接可选**：`queryShowLink`（面板「监控设置 → 展开编辑 → 查价附带链接」）默认开着，每条下面带原文链接；关掉只报价格和平台，末尾会说明「链接没打开」。

## 价格记忆

查到的价格不止留在本插件的记录里，还会写进她的**记忆**：以后被问到「上次那个耳机多少钱」「我上回查的咖啡机降了吗」，她能想起记忆里那条，而不是现编一个数。

- **什么时候写**：`/查询价格`、`price_query` 工具、面板「查询价格」、加监控时，以及后台每轮检查看到的新价格。一次查询只写一条，写的是**这次真正查的那件商品**（按相关度挑，不是最便宜的配件）。
- **单独删**：面板「价格记忆」每条右侧都有「删除」（点了先确认再删，只删那一条）；QQ 里用 `/忘掉价格 3` 按编号删、`/忘掉价格 咖啡机` 按关键词删、`/忘掉价格` 全清。
- **写什么**：商品名、平台、价格、查询时间；如果比记录最低还低、或者比上次便宜，也会写进去。一条不超过 200 字，带 `价格监控` / `价格` 标签，来源是 `price-watch`。
- **一条商品一条记忆**：按商品指纹去重，同款再查是更新那一条（记忆模块不认 `validUntil` 的老版本会删旧写新），不会越查越多。
- **保留多久**：`memoryTtlMinutes` 决定，**默认 30 分钟**，0 = 永久。价格是有时效的——「半小时前查的 899」和「三天前查的 899」不是一回事，留太久会让她拿过期价当真。到期后记忆模块自己判定它失效，不会被想起，但仍在记忆库里看得到，直到常规清理。
- **升级兼容**：老配置里的 `memoryTtlDays`（按天）和 `memoryTtlHours`（按小时）会在启动时自动换算成分钟（3 天 → 4320 分钟），用户设过的值不会被悄悄丢回默认。
- **记不住也不影响查价**：记忆模块没装、被关掉、或者写入失败时，查价和提醒照常工作，只是少一条记忆。

写不写由面板「监控设置 → 展开编辑 → 更多设置」里的**查到的价格写进记忆**、**价格记忆保留**两项控制（默认开、30 分钟），也可以在设置里直接改 `memorySync` / `memoryTtlMinutes`。改完对新写入 / 刷新的记忆生效。

记忆模块自己的总开关在面板「心情」页的「记忆」里（`config.memory.enabled`）；那边关掉时这边也写不进去，面板的「价格记忆」卡片会直接说「记忆模块没在跑」。

> 「记忆里的价格」是**当时查到的爆料价**，不是现在还能买到的价格。隔了几天再问，要按「上次查的时候」来说，别当成当下的报价。

## 匹配与排序

搜到的爆料里常混着配件、耗材和同系列的其他型号，所以「最低」不等于「你要的那件最便宜」：

- **品牌中英对照**：说「拓竹」，标题写 `Bambu Lab` 也算命中；红米 / REDMI、任天堂 / Nintendo 同理。
- **型号按边界认**：`A1` 认 `A1`、`A1 Pro`（同系列，算候选但会排在同款后面），不认 `A1C`、`A1mini`、`A2L`——那是另一个 SKU，不能拿它的价格冒充。
- **配件降权**：「耗材 / 配件 / 打印板 / 贴膜 / 保护壳 / 收纳包」这类标题，在查询自己没提这些词时会被标成【配件】并排到主商品后面。所以搜「拓竹 A1」先看到的是 ¥872 的打印机，不是 ¥17 的打印板。
- **没有强相关结果时**会明说「没有完全对得上的，最像的 N 条」，而不是把一堆弱相关也叫做「最低」。

## 她不会「没查就说查过了」

模型有时候不调用 `price_query`、直接凭印象来一句「查过了，库里只有耗材爆料，没有整机价」。这句话既没有数据支撑，又会把用户引向错误结论（实际上库里有 ¥872 的整机）。

扩展在 `reply` 事件里加了一道闸：她的话里出现「查过了 / 查了一圈 / 库里只有 / 数据库里 / 只有耗材 / 全是耗材 / 没有整机价 / **没整机价**（省了「有」字）/ 查不到 / 搜不到 / 没找到」这类**声称查过或断言库里没有**的说法，而这一轮（两分钟内）根本没有真实查询记录时：

1. 从她的话里还原要查的商品（优先「品牌 + 型号」，如「拓竹 A1」；品牌只认已知品牌或品类词，避免把「没有整机价 A1」当成商品名）；
2. **代码替她真查一次**；
3. **整段换成真实结果**：不打捞她原来的文字，只保留表情/语气。因为她这句话已经证明不可信，实测还会裹着上一轮聊别的话题的残句（「涩图这个别找我」）和 `[沉默]` 标记；
4. 补查失败 → 说「这次没查到，过会儿再试」；模块关着或群不在白名单 → 说「这个我查不了」。**错误结论在任何路径下都不会原样发出去**。

刚用工具查过的两分钟内不重复补查，避免一次问价刷两遍。

## 她不会把工具标记发给群友

模型偶尔会把工具调用当普通文字写出来，比如 `<price_query><query>拓竹 A1</query></price_query>`，以前会原样进 QQ。现在扩展在 `reply` 事件里先剥掉这些标记：

- **查价 / 看列表 / 立即检查**这几个只读操作，剥完标记后**替她真跑一次**，把结果接在正文后面——她本来就想查，只是写法错了。
- **加监控**这种写操作不代执行，只留一句「发 /监控价格 商品名 就行」，免得群友靠打字触发写入。
- 剥完什么都不剩时，不会发「等结果出来再说」这种占位话，直接给查到的结果。

## 谁能用

**群聊白名单默认是开着的**：群号没写进白名单之前，群里发什么命令都只回一句「这个群还没加进价格监控白名单」。先在面板「系统 → 价格监控」的「允许的群」里一行一个填上群号，那个群才能用。私聊不受限制（主人自己的私聊就是管理入口）。关掉 `groupWhitelist` 就回到「所有群都能用」。

> 宿主自己还有一层群白名单（面板「系统 → 权限」里的 `allow.groups`）。不在那层的群，消息根本到不了扩展，所以两边都要加。这里这层管的是「哪些群能用价格监控」，比宿主那层更窄。

Aurabot 的 `api.command` 只对主人开放，所以群友的命令是扩展在 `message` 事件里接管的（返回 `true` 就这条不再交给她回）：

- `/价格监控帮助`（旧写法 `/价格帮助` 也认）：所有人都能用（白名单外也能看用法）。
- `/查询价格`：非主人要 `guestQuery` 打开；关掉只回「查价只有主人能用」。
- `/监控价格`：非主人要 `guestWatch` 打开（默认关）；关掉只回「加监控只有主人能做」。
- `/价格列表`、`/取消监控`：只给主人，非主人一律回「监控列表只有主人能看」。

监控本身按聊天分开：列表、取消和提醒都只作用在发命令的那个聊天里。

## 面板

入口在 Aurabot 面板的**「系统」组**下面，自己占一页，不塞进别页。「价格监控」不命中宿主按名字猜分组时的「平台」类关键词，所以落在系统组。

模块定义里**不写**自定义分组字段：扩展模块自定义分组在不同宿主版本上识别不一致，写死反而会出现「这个版本在平台、那个版本在系统」的分裂；统一交给宿主的默认规则，实际落点就是「系统」组（排在「日志」前面）。注意也不是 `tab`——`tab` 会把内容塞进某个内置页内部。

**总开关就在这一页里**：它挂在「价格监控」卡片右上角，和监控列表、查价框在同一页。定义里 `defaults` 和 `settings` 都**故意**没有 `enabled` 这一项——宿主只要看到它，就会在页面标题栏再画一个总开关、并把设置自动表单再列一遍，等于同一页两个开关、两份设置。设置项全部由 `panel.js` 自己渲染。

**标签页上的开/关小圆点还在**：模块定义里写了 `flag: 'active'`，圆点读的是 `active`、默认亮着；面板拨开关时会同时写 `enabled` 和 `active`，启动时也会把老配置里只有 `enabled` 的情况对齐到 `active`。之所以不直接把圆点绑到 `enabled`：宿主对 `flag === 'enabled'` 的模块会顺手在页面标题栏再画一个总开关，那就又变两个开关了。

面板通过扩展自己注册的接口读写状态：

| 接口 | 作用 |
| --- | --- |
| `/state` | 当前开关、监控列表、当前监控商品的本机价格记录、上次检查结果 |
| `/search` | 按关键词查一次价格（按平台分组），顺手记录看到的价格 |
| `/add` | 添加监控；一次没匹配到唯一商品时返回带 `articleId` 的候选。再调一次时把选中的 `articleId` 一起传（`{ query, articleId }`），才会精确认领那一条爆料 |
| `/remove` | 按 id 取消监控 |
| `/check` | 立即检查一轮（可只查某一条） |
| `/memory` | 价格记忆列表、保留天数、记忆模块在不在；`POST { clear: true }` 清空 |

面板里加的监控记在主人私聊（`private:主人QQ`）名下，所以在 QQ 里用主人私聊发的 `/价格列表` 才看得到它们。设置改完保存立即生效，不用重载模块（模块每次都重新读 `api.settings()`）。

关掉总开关后：不再定时检查、不发提醒，监控列表和本地最低价都保留；QQ 里的命令仍会回一句「价格监控关着」，不会静默。

这些接口只接面板自己的同源调用：请求带 `sec-fetch-site: cross-site`、或 `Origin` 与 `Host` 对不上的直接拒绝；`/search`、`/add`、`/remove`、`/check` 还要求 POST，GET 一律不处理。

| `intervalMinutes` | 60 | 后台自动检查的间隔（分钟），范围 10–1440 |
| `alertDropPercent` | 5 | 降价提醒的降幅百分比阈值；0 = 只按金额判断 |
| `alertDropAmount` | 5 | 降价提醒的降幅金额阈值（元）；0 = 只按百分比判断 |

| `queryPages` | 2 | 每次查询翻几页列表，范围 1–5，每页 50 条 |

## 防止刷屏

价格提醒最容易变成深夜一堆消息，所以有几道闸：

1. **查价只列几条**：`/查询价格` 默认只把最便宜的 3 条列出来，而不是每个平台的报价全铺一遍；条数用 `queryTopN` 调，1–20。
2. **链接可关**：`queryShowLink` 关掉后每条只剩「¥872 · 拼多多 标题」，网址不再刷屏；要看原文再打开。
2. **监控时段**：`checkStartHour` / `checkEndHour` 之外不自动检查（默认 0 至 0 = 全天）。想只在白天盯，就设 9 至 23；想避开半夜，设 8 至 24 之类。手动「立即检查」不受限。
3. **每轮上限**：一次最多查 `maxChecksPerRun` 个（默认 5），剩下的等下一轮，不会一口气把十几种商品的提醒全打出来。
4. **检查间隔**：同一个商品至少隔 `intervalMinutes` 才查第二次（默认 60 分钟）。
5. **提醒冷却**：同一件商品两次提醒至少隔 `alertCooldownMinutes`（默认 180 分钟），同一波行情不会连着播报。
6. **好价只报一次**：超级好价 / 早期好价只在这个等级第一次出现时提醒，之后持续处于该等级不再重复。
7. **只有真变化才提醒**：价格没动、没创新低就不发；首次看到某件商品只记下价格，不当成「创下最低」来告诉你。

## 限制

- 数据全是值友爆料：标题、价格、平台、购买条件都来自爆料原文。价格常常带「需用券 / 需买 N 件 / 叠加满减 / 限地区」这类前提，**实际到手价以原文（爆料的商品链接）为准**。
- 不保证覆盖全部平台，也不保证每件商品都有爆料：新上架、冷门型号、非电商渠道的商品很可能搜不到。
- 一条爆料不等于全平台最低价，也不构成购买建议。判不判好价只说明社区互动够不够热。
- `/查询价格` 先按相关度、再按价格排序，配件 / 耗材会压到主商品后面并标【配件】；但标题里带关键词的不同规格仍可能混进来，下单前看一眼标题，别只看数字。
- 检查一条监控时，先按商品指纹认同一件商品；认不出来就退回标题最相近的爆料，再不行才取价格最低的那条更新价格。
- 没有强相关的多条结果时，会把最接近的几条当候选列出来等你按编号选；连候选都没有就直接说没找到，不会硬塞一条。候选只按标题相关度排，不保证就是你要的那一款。
- 列表接口只给当前快照：商品掉出列表后就查不到，那段时间的价格不会进入记录。
- 接口改版、限流或网络不通时，这一轮检查会失败：失败只写日志、面板上显示原因，不会被当成降价；失败的那条按指数退避（间隔翻倍，最长 6 小时）再试，其他监控仍按原来的间隔轮换，不会被前几条坏数据永远挡住。
- 定时器每分钟判一次到期，实际检查时间可能比 `intervalMinutes` 晚一两分钟。

## 隐私与安全

- 唯一的出站请求是对 `api.smzdm.com` 的 HTTP GET（`/v1/list`），带 12 秒超时。查询参数只有关键词、条数、翻页偏移；请求头是一个普通浏览器 UA、`accept: application/json` 和来源页 `referer`，不带 Cookie，不登录，不读、也不上传任何用户信息。
- 发值得买链接时会额外请求一次爆料页（只读 HTML，取 `og:title`），同样不带 Cookie。
- 监控列表和价格记录只写本机数据目录 `modules-data/price-watch/state.json`（原子写入），不上传、不外发。
- 价格记忆调的是 Aurabot 内置记忆模块的公开导出（`add` / `update` / `remove` / `list`），写进的是本机 `memories.json`，和记忆模块的其它内容一样只在本机、不上传。清掉用 `/忘掉价格` 或面板「清空价格记忆」。
- 提醒只发到**添加监控的那个聊天**（`private:QQ号` 或 `group:群号`），不会跨聊天广播，也不会主动私聊别人。
- 命令回复只回到发命令的聊天；群里的 `/价格列表` 不会把别的聊天的监控列出来。
- 爆料标题、价格等是不可信的外部文本：只用于展示，不会被当成指令执行。
- Aurabot 的试运行（`dryRun`）开着时，本该发的提醒只写日志，不真的发到 QQ。
- 提醒只有在 `api.sendText` 真的发出去之后才计次数、占冷却；发送失败、试运行拦下、群移出白名单都不会占掉冷却，也不会让面板的提醒数虚高。

## 给她用的工具

除了命令，扩展还注册了四个工具，让她自己判断什么时候用：`price_query`（查多平台价格，**顺手把价格记进记忆**）、`price_watch_add`（加监控）、`price_watch_list`（看监控列表）、`price_watch_check`（马上检查一轮）。加监控这类写操作只认主人，查询不受限。

`price_query` 的返回里会多一句「这次的价格已记进记忆，保留 N 天」（或者说明记忆这会儿写不进去），她照着这句说就不会把「记下来了」说成空话。
