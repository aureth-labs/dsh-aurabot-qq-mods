# 工作群

群成员全是自己人的群，自动进工作状态：每条消息必回，主人在这些群里说话时给完整本机工具，
还能单独指定模型和思考强度，并且群里不发任何表情。

几个人的小群在群里说事，比来回私聊顺手 —— 但群里没人 @ 她，普通群聊策略下她多半不吭声。
这个模块就是给这种群开的：成员只有白名单里的那几个，那就没必要等她被叫到。

## 装法

在模块市场安装「工作群」，然后在面板里填**工作群白名单 QQ**（一行一个，除主人本人以外的人）。

不填名单时怎么都不会有群被判成工作群 —— 判定条件是「这个群的成员，除了机器人自己，
每一个都在名单里，并且主人在里面」，所以名单必须先把群里其他人写全。

装好以后几分钟内生效，不用重启。面板「已安装」页能看到 `workgroup` 在不在跑，
它的设置在模块自己的设置页里。

## 判定规则

每 120 秒（可改）后台扫一次群列表和成员，扫的时候不阻塞聊天：

- 群里有主人，**并且**所有成员都在「白名单 + 主人 + 机器人自己」里 → 判成工作群。
- 只要混进来一个名单外的人 → 立刻不再是工作群。
- 群人数没有上限，但成员读取要靠网关，群特别多的时候可以把间隔调大一点。
- 读成员失败（网关超时、返回空表）时沿用上一轮判定，连续 3 轮都读不到才摘掉。
  一次抽风不该让「必回」和工具当场失效，但也不能因为网关长期不通就一直给权限，所以有个上限。

判定结果只在内存里，重启后由启动那一次扫描补回来。

## 判成工作群以后

**每条必回。** 群里任何人的消息都算叫到她，不用 @，也不会用 `[沉默]` 躲开。
她那边会收到一条工作方式规则：说话简短直接、先给结论再给细节、做一小步汇报一小步、
要改动任何东西先说想改什么再等点头 —— 而不是平时那种闲聊口气。

**给主人完整本机工具。** 打开宿主已有的 `group.ownerTools`，并且只对判定出的群生效
（写入 `group.ownerToolsGroups`），其他白名单群不受影响。面板里「工作群给主人完整本机工具」
关掉的话，本模块就不再碰这两个字段。

**独立模型（可选）。** `provider` / `model` / `reasoningEffort` 三项，留空就跟随全局。
工作群里用贵一点的模型、开更高的思考强度，别的地方照旧，这是这个模块最初想解决的问题。

**群里不发任何表情。** 这条是硬拦，不是写进规则让她自觉：表情是在她的回复**拆好段之后**
才补上的，所以模块在 `reply/items` 里把 `sticker` 段整段摘掉；绕过前者的发送（慢工具提示、
模块代发）在最终出口 `send` 上再拦一次，认「本地表情图 `sub_type=1`」和「商城表情 `emoji_id`」
两个标记，**真图片不会被误伤**。表情被摘光的那一轮就不发，不拿别的东西凑数。
私聊和不在名单里的群一个字不动，那边照旧。

**判定结果也能同步进 `group.workGroups`。** 这是给「宿主侧按 `workGroups` 做隔离」的源码分支用的
（比如 `dsh-aurabot-qq` 里「工作群剥掉心情、语气、日记等社交上下文」那套机制）。
上游没有这个字段，写了不会生效，也不会报错；不想要就关掉「把判定结果同步进 group.workGroups」。
注意两边留空的语义是**反的**：`ownerToolsGroups` 留空 = 所有白名单群，`workGroups` 留空 = 没有工作群。

## 本机工具这一档的边界

上面那条「完整本机工具」的实际效果是：**主人在这个群里说话的那一轮，工具齐全；
别人说话的那一轮，全局工具整层被收走。** 不是「群里谁问都给」。

这是宿主定下的规矩，写在这里免得装完以为是模块坏了：

> 群里任何人都能驱动本机读写，权限面太大，明确不做。

所以「成员都是自己人」并不等于「每个自己人都能让她在你机器上跑命令」。真要让某个人也能驱动本机，
得把他加进主人那一侧 —— 那是权限模型的问题，不是这个模块能绕的。

判定和工具是两件事：判定成工作群了，「必回」和「规则」对所有成员都生效，只有工具那部分按上面这条走。

## 命令（只有主人能用）

| 命令 | 作用 |
|---|---|
| `/工作群` | 看当前判成工作群的群（带群名）、白名单、本机工具开没开 |
| `/工作群 重扫` | 立刻重扫一次，不等下一个间隔 |

## 权限

| 能力 | 用途 |
|---|---|
| `plugin-config` | 读写插件配置里的 `group.ownerTools`、`group.ownerToolsGroups`（开工具）和 `group.workGroups`（同步判定结果） |
| `plugin-internals` | 只为 `/工作群` 里显示群名，调 `api.core.hub.groupName(groupId)` |

## 说明

- 只通过 OneBot 调用 QQ（`get_group_list` / `get_group_member_list`），不访问其他网络地址。
- 不硬编码任何 QQ 号：白名单在面板里填，源码里没有真实号码。
- 不改人格文件，不删聊天记录，不往共享记忆里写东西。
- 没有额外依赖，Windows、macOS、Linux 都能跑；目前只针对 QQ 群。

关掉模块后不再扫描、不再注入规则、不再拦表情，已经写进 `ownerToolsGroups` / `workGroups`
的群号也不会自动清掉 —— 需要的话把那两个开关关掉，或者手动清空名单。

读不到成员一律不算）、白名单解析、扫描间隔下限、`group.workGroups` 同步、工作群摘表情
（两个出口都测，真图片不误伤），以及「源码里没有任何硬编码 QQ 号」。
