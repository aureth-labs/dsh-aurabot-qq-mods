# 模块心愿单 · AuraBot 模块

让 AI 自己读最近的聊天，发现「她还缺什么能力」，私信主人问要不要做；主人回复同意后，直接生成一段能复制给 AI 的模块开发提示词。

## 做什么

1. **偷偷攒聊天**：必须先在设置里勾选同意《使用协议》才会开始。只在内存里留最近 400 条消息（每条截到 160 字），群聊和私聊都会收，跳过命令、空消息；手机号、身份证、邮箱、银行卡、门牌地址会先替换成 `[手机号]` 之类的占位符，再交给模型。她自己的回复也留一份（标成「她」），方便看出她哪里答不上来。
2. **定期自省**：默认每 6 小时、且至少攒够 20 条才分析一次。把片段交给模型，找出用户明确需要、但她做不到或做得很差的具体需求。
3. **私信主人**：每条建议带编号、现象、能否做的结论和理由、需要哪些能力、需要主人提供什么。
4. **主人拍板**：
   - `可以 3` → 生成开发提示词，私聊发给你
   - `不用 3` → 跳过
   - `#提示词 3` → 把之前的提示词再发一次
   - `#自省` → 马上分析，不等定时

## 命令

群聊里必须带 `#`，私聊可以省略。

```text
#自省            马上读最近的消息，找需求
可以 3           同意第 3 条，生成提示词
#可以 3          同上（群里用）
不用 3           跳过第 3 条
#提示词 3        重新发送第 3 条的提示词
#忘掉我          删除自己的缓存并永久不再被记录（任何人都能用）
```

除 `#忘掉我` 外，只有主人（Aurabot 配置里的 `ownerQQ`）能用，其他人发这些不会有反应。没有编号时，只有一条待决定才会直接采用；有多条会列出编号让你选。只认「可以 / 同意 / 做吧」这几个词，平时说「好」「行」不会误触；没有待决定需求时，私聊里裸说「可以」也会原样交给她正常聊天。

## 提示词里有什么

生成的提示词包含三块：

1. **需求**：聊天里暴露的问题、期望行为、建议声明的能力、需要主人提供的东西。
2. **交付要求**：目录结构、README / LICENSE、能力声明要和实际一致。
3. **官方规范**：仓库地址、模块至少四个文件、`module.json` 必填字段、`category` 取值、六个 `capabilities` 的含义、`npm run catalog / check / pack`、PR 模板与红线（不发 Cookie、不群发、不绕过验证码、`plugin-internals` 的任务书只能来自主人意图等），以及官方教程链接。

想追加自己的要求（或把官方另外给的提示词原文贴进去），填设置里的「附加到提示词末尾」，会拼在最后。

## 使用协议

**安装后默认不工作。** 必须在设置页勾选「我已阅读并同意《使用协议》」才会读取聊天、分析并私信；不勾选时模块只加载、不做任何事。

勾选即表示你确认并同意：

1. **你是数据控制者**：由你决定在哪些群启用。请只在你负责管理、且成员知道机器人功能的环境里使用。
2. **会读取聊天内容**：群聊和私聊消息都会进入内存缓冲，打码后发送给当前配置的模型。不想让模型看到的内容，不要把机器人放进那个群。
3. **已做最小化**：只留最近 400 条、每条 160 字；手机号、身份证、邮箱、银行卡、门牌地址会被替换成占位符；不留历史聊天，分析完立即清空内存。
4. **用途单一**：只用于发现「她缺什么能力」，不用于营销、画像、转卖或公开。
5. **可随时停止**：关掉设置里的「启用」或卸载模块即停止收集；任何成员发 `#忘掉我` 可删除自己的缓存并永久不再被记录；已生成的建议可以在设置里或本地状态文件中删除。
6. **未成年人**：若群内有不满 14 周岁的成员，其聊天内容属敏感个人信息，需要监护人同意；不确定时请不要在该群启用。
7. **风险自负**：模型建议可能有误，是否采纳、是否按提示词开发由你决定并承担后果。

不同意以上条款请保持开关关闭或卸载模块。

### 可能存在的法律问题（请知悉并自行评估）

这个模块读的是聊天原文，比只处理公开资料的模块更敏感。以下是主要风险，模块做了技术缓解，但**不能保证在所有司法辖区都合法**：

1. **告知与同意（PIPL 第 13、17 条）**：你勾选协议只代表你作为部署者同意，不等于群成员同意。建议在群公告/群规写明「机器人会为发现自身不足而读取群聊，并先打码再交给模型」。
2. **敏感个人信息（第 28 条）**：未成年人信息、身份证、健康、行踪等属敏感个人信息。模块会替换常见格式，但无法识别自由文本里的敏感内容；有未成年人的群不建议启用。
3. **向第三方/境外提供（第 38、39 条）**：聊天内容会发给当前配置的模型。如果模型服务在境外，可能构成跨境提供个人信息，需要单独同意；对合规要求高的场景，请改用本地模型。
4. **隐私权（《民法典》第 1032、1033 条）**：持续读取并分析群聊可能被认为侵扰私人生活安宁；只在你负责管理、成员知情的群里使用。
5. **平台规则**：腾讯对非官方客户端和自动化行为有条款限制，账号风险由使用者承担，与本模块无关但同样适用。
6. **建议的责任**：模型给出的「可以做」只是技术判断，不代表合规。按提示词开发出的模块若违反法律或平台规则，责任在开发者和使用者。
7. **删除权（第 47 条）**：模块提供 `#忘掉我` 删除缓存并永久停止记录；已生成的建议可在 `state.json` 里删除。删除请求只作用于本模块，不影响 Aurabot 自身的聊天记录。
8. **不同地区**：中国大陆适用《个人信息保护法》，台湾适用《个人资料保护法》，香港适用《个人资料（私隐）条例》，要求不完全相同；本模块按「最小必要 + 告知 + 可撤回」设计，是否满足当地要求需自行判断。

### 合规设计（模块做了什么）

- 默认不工作，必须显式勾选协议
- 只留最近 400 条、每条 160 字，分析完立即清空，不保存历史聊天
- 手机号、身份证、邮箱、银行卡、门牌地址在进模型前打码，模型输出落盘前再打码
- 只用于「发现能力缺口」这一个目的，不营销、不画像、不公开
- 任何人都能 `#忘掉我` 撤回；名单只存 QQ 号
- 不访问外网，只调用宿主已有的模型接口；建议只私聊主人

## 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 我已阅读并同意《使用协议》 | 关 | 不勾选就完全不工作 |
| 启用 | 开 | 关掉后不收集、不分析 |
| 最少隔几小时分析一次 | 6 | 1~72 小时 |
| 至少攒多少条消息 | 20 | 不够就不分析 |
| 最多挂几条待决定 | 5 | 超出丢最旧的 |
| 附加到提示词末尾 | 空 | 可选，拼在提示词最后 |

## 隐私

- 聊天内容**只存在内存里**，分析完立刻清空；不写 `state.json`，不保存历史聊天。
- 进缓冲前会先打码：手机号、身份证、邮箱、银行卡、门牌地址替换成 `[手机号]` 这类占位符；模型写出的建议在落盘前再打一次码。
- 落盘的只有：建议标题、模型概括的一句话现象、结论、编号、已生成的提示词（方便重发）、上次分析时间，以及 `#忘掉我` 的 QQ 号名单；不保存原始消息。
- 分析走插件自带的 `api.ask`（和平时对话同一个模型），不额外访问外网。
- 建议只私聊发给 `ownerQQ`；除非主人主动在群里发 `#可以`，否则不会把建议发到群里。

## 限制

- 建议是模型判断的，会有误报；默认宁缺毋滥，最多 3 条，重复标题会被去重（相似度 ≥ 0.6 视为同一条）。
- 明显的红线需求（要密码 / Cookie / 验证码、群发、批量加好友、刷量）会被直接标成「不建议做」，但仍会告诉主人。
- 不读取历史消息，只从现在开始攒；刚装好要等攒够条数才会有第一条建议。
- 打码靠正则，只能覆盖常见格式；昵称、住址描述、病情等自由文本无法可靠识别，敏感群不要启用。
- 模型调用失败时，这一轮消息会放回缓冲，发 `#自省` 或等下一轮巡检都能重试（失败不会推进「上次分析时间」）。
- 私信发送失败时，这一轮建议会被回滚，不会留在去重记录里，下次分析会重新发现。
- 不做「已有模块是否覆盖」的全量比对，判断依赖提示词里的常见功能排除列表；主人看到明显重复的直接回「不用」即可。
