# 识图（shitu）

**给看不了图的模型配一双只认字的眼睛。**

别人发来图片、表情包、截图，先把里面的字读出来，再把文字交给她。
全在本机跑，图片不离开这台电脑。

## 它解决的问题

她用的模型有时候是纯文本的（便宜的、本地的、或者主人给某个私聊单独指定的），
这种模型收到图片只能拿到一句「这里有 1 张图，你看不了」，等于瞎了。

表情包尤其明显：一张「笑死」配大字的表情，人一眼就懂，纯文本模型只能干瞪眼，
回一句「这图没加载出来」或者干脆装作看不见。**这个模块就是把表情包、截图、
聊天记录图里的字抠出来喂给她**，让她至少知道图上写了什么。

图里一个字都没有的时候（照片、纯表情、无字梗图），可选地借一个**能看图的模型**
补一句客观的画面描述，否则她确实只能看到「一张图」。

## 行为

| | |
|---|---|
| **何时动手** | 挂在 `prompt` 阶段，把图片块原位换成文字块：顺序不变，也不会触发 hub 那句「你看不了图」的降级提示 |
| **永远先 OCR** | 不管当前模型能不能看图。模型元数据写着 `vision: true` 不代表这一轮真的把图送到了（附件中间层丢图、历史图被 offload 都会让它看到空白），拿它决定「跳过」等于把唯一的保底关掉 |
| **只有标点不算有字** | 表情包上独一个「?」时，OCR 会读出 1 个字符。判定按「去掉标点/符号后还剩几个字」，只剩标点就走画面描述 |
| **读不出字** | 一个字都没认出来 → 只给格式尺寸，不塞空壳 |
| **缓存** | 同一张图（表情包、反复转发的梗图）第二次直接命中，不再起进程 |
| **一条多图** | 最多同时读 N 张（默认 3），合并成一次调用，模型只加载一次 |

## 它做不到

**只认字，不认识图。** 猫、场景、长相、好看不好看、表情是开心还是生气——OCR 读不出来。
开了「补一句画面描述」才会有一句客观描述；关掉之后她只知道图里有什么字。

## 会访问哪些网址

**只有安装时**，pip 镜像（默认 `https://pypi.tuna.tsinghua.edu.cn/simple`，可在设置里换成官方源或别的镜像）。

用到的包：`rapidocr-onnxruntime`、`pillow`、`numpy`。
**第一次安装约 320MB**（含 PP-OCRv4 的检测 / 识别 / 方向分类三个 ONNX 模型，共约 16MB）。

运行期**没有任何网络请求**，图片不出本机。

例外是「补一句画面描述」：那一句是走 Aurabot 自己的模型接口（`api.ask`），
和你平时聊天用的是同一套 provider，发出去的是这张图本身。**不需要这个功能就关掉它**，
模块就完全不产生任何外部请求。

## 会写入哪些文件

`modules-data/shitu/ocr/`（设置里可改到别处）：

- `ocr_core.py`、`ocr_run.py`、`ocr_mcp.py`、`selftest.png`、`.shitu-ver`
- `.venv/`：独立 Python 环境，约 320MB（含 `.shitu-owned` 归属标记）
- `ocr-cache.json`：识别缓存，最多 500 条，**只存文字不存图**

### 不会动你已有的环境

这条是硬约束，写死在 `lib/env.mjs` 和 `lib/install.mjs` 里：

| 情况 | 行为 |
|---|---|
| 目录是空的 / 是本模块铺过的 | 可以写、可以装 |
| 目录里有别的东西但没有 `.shitu-ver` | **一个字节都不写**，报错让你换空目录 |
| 目录里已有一个不是本模块建的 `.venv` | **不删、不覆盖、不打标记**，报错 |
| 系统 python 里本来就有 rapidocr | **只借用**，不升级、不往里装东西 |
| 找不到 python | 明确报错，不自己下 exe |

「是不是本模块建的」靠两道判据：`.venv/.shitu-owned` 标记，或者 `pyvenv.cfg`
的 `command` 行里同时有 `shitu` 字样和这个 venv 的目录名。老版本建的会自动认领，不用重装。

## 怎么用

面板「本地接口」页最下面的「识图 · 本地 OCR」卡片：

1. 点「安装引擎」，等进度到 100%
2. 打开设置里的「识图总开关」，保存
3. 「试一张」填个本机图片路径，或直接选文件

装好之后不需要每次管它。想让她连表情包上的字也读到，把「只在模型看不了图时识别」关掉。

命令（只认主人）：`/识图`、`/识图 状态`、`/识图 装`、`/识图 测 <路径>`、`/识图 看 <路径>`、`/识图 清缓存`。
工具：`shitu_read`（`last` / `quote` / 本机绝对路径），她自己决定什么时候用。

## 出问题

| 状态 | 意思 |
|---|---|
| 就绪 | 正常 |
| 就绪（借用系统环境） | 系统里本来就有 rapidocr，能用，但建议装一份独立的 |
| 有 Python，缺引擎 | 点「安装引擎」 |
| 安装中 · …% | 等，首次装包比较慢 |
| 不自动安装 | 目录里有别人的东西，或 venv 不是本模块建的。换成空目录再试 |
| 自检失败 | 错误原文就在卡片上 |

## 测试

```sh
node --test test/*.test.mjs
```

| 文件 | 覆盖什么 | 要不要引擎 |
|---|---|---|
| `test/env.test.mjs` | 归属判定与安全边界：别人的目录、别人的 venv、老版本认领、半成品目录 | 不要 |
| `test/content.test.mjs` | `isSubstantive`（只有标点不算有字）、设置项一致性、工具注册、钩子兜底 | 不要 |
| `test/describe.test.mjs` | 格式嗅探、宽高解析、动图判定、画面描述的失败保底 | 不要 |
| `test/ocr.test.mjs` | 真跑一次识别、缓存命中、坏数据不崩 | **要**（没装就自动 skip） |

前三组是纯本地断言，CI 里会跑；第四组需要本机装了引擎，没装时整组 skip，
所以 CI 不会因为它变红。想在本地验证真实识别：

```sh
SHITU_ENGINE_DIR=<装好引擎的目录> node --test test/ocr.test.mjs
```

## 依赖

- Python 3.9+（优先自动找 DSH 自带的运行时 python）
- 约 350MB 磁盘
- 不需要 GPU，装完之后不需要联网
