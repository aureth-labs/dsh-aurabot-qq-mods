# 官方机器人接入（roost bridge）

给大肥鱼一键装 [roost](https://github.com/tdcq9594/qq-bot-roost) 框架、开它的 OneBot v11 兼容层，把大肥鱼的 QQ 网关从 SnowLuma/NapCat 这类注入式网关换成 **QQ 官方机器人接口**。

## 它做什么

大肥鱼本来只认 OneBot v11（正向 WS + HTTP action），roost 本来只走官方接口。roost 里已实现的 **OneBot 兼容层** 把两边接起来：官方事件翻成 OneBot 事件、OneBot action 翻成官方 API。这个模块是那座桥的**配置向导 + 兼容说明**，不改大肥鱼、不改 roost 的源码。配套 roost 框架也由本人开发（`tdcq9594/qq-bot-roost`，package.json 署名「倦飞之鸟」），这里随包附带的是其 1.1.7 发版原样副本。roost 是**模块自带、启动时整体复制到数据目录运行**的——不联网下载、不改框架源码。

链路：`QQ 官方 → roost（官方接口）→ OneBot 兼容层 → 大肥鱼（零改动）`

## 怎么用

1. 面板「官方机器人接入」页按顺序点：**启动 roost → 生成二维码 → 手机 QQ 扫码确认** → 等提示「凭证已写入 roost，进程已重启」→ 一键配置。扫码成功后模块会**先关掉 roost、把凭证写进配置、再拉起**（十几秒，面板会短暂打不开），这样 roost 内存里才不会留着空 AppID/AppSecret 把新凭证覆盖掉。此时**先别接入**：让 roost 跑一会儿、群里正常聊天（大肥鱼仍连旧网关，不受影响），去 roost 面板「身份」页把常用用户 QQ 号绑定好，最后再点「接入大肥鱼」→ 重启 DSH。这一步会把网关、HTTP/WS 地址和 token、以及 aurabot 顶层 `botQQ` 一起写好（你自己的 `ownerQQ` 不动）；**只在模块里保存 QQ 号不会改 aurabot，必须点「接入大肥鱼」**。这一步还会暂关**空间日记 / 空间互动**（依赖 QQ 空间私有协议，官方这条路用不了），点「一键改回原网关」会还原。这样切过来记忆直接对上真号。
2. 扫码建机器人走的是 roost 框架自带的 `/api/bots/qr/start` + `/qr/poll`（官方绑定页），模块只透传、不碰 `bindKey`、不重实现协议。手机 QQ 扫码就拿到 AppID/AppSecret，建机器人凭证不用自己去开放平台抄（改资料仍要登录，见第 3 步）。扫码失败可在页面折叠区手填 AppID/AppSecret 兜底（同样走「先停、再写、再起」）。
3. 还要自己确认：开放平台后台打开「接收所有消息」（群聊全量消息必须开）、把机器人拉进群、aurabot 面板总开关打开且试运行关掉（接入后模块会提示当前状态）。要改机器人**头像 / 昵称 / 简介**的话，先去 roost 面板「开放平台」页扫码登录开发者后台：这些走官方后台 CGI，不是 OneBot 能力，没登录会报「还没登录开放平台」；扫码建机器人只给 AppID/AppSecret，不等于登录态。
4. 卡住了点「一键诊断」，逐项查出面板通不通、机器人在不在线、兼容层开没开、网关指没指。

几个省心点：
- **整体复制到数据目录、数据隔离**：模块自带 `lib/vendor/roost/` 是只读母本；就绪/启动前整份同步到 `modules-data/roost-bridge/roost-code/` 并从那里运行（按内容指纹判断，模块升级自动重复制）。roost 会把 `data/ports.json`、空 `plugins/` 写在自己的代码目录，现在都落在数据目录，不会弄脏被宿主监控的模块目录、也不触发热重载。运行数据（config/logs/data）仍用 `ROOST_HOME` 指到 `roost-home/`，凭证不随代码复制。
- **端口不用管**：roost 面板端口被占会自动顺延，模块读 `data/ports.json` + `/healthz` 自动找真实端口，不用你改配置。
- **密钥只存内存**：扫码拿到的 AppID/AppSecret 暂存内存；**等 roost 停稳后**才写进 roost 自己的 `config/bots/*.json` 并回读校验，再启动让配置生效。面板 accessKey/兼容层 token 只存内存，DSH 重启后按提示重填即可（roost 那份仍在，通常不用动）。
- **一键退出**：「一键改回原网关」把大肥鱼的网关恢复成原来的 SnowLuma 配置。
- **可选自动拉起**（设置里的开关，默认关）：打开后，DSH 加载时若「已配置完成 + 网关指向兼容层 + roost 没在跑」三条同时成立，会延迟 8 秒自动起一次 roost。**不会一装模块就起进程**，你只是想聊大肥鱼也不会被莫名拉起。凭证已经写在 roost 自己的配置里，所以 DSH 重启后内存密钥清空也不影响自动拉起。开关改动要重启 DSH 才生效；上次自动拉起的结果在面板和「一键诊断」里能看。

## 为什么用 roost，而不是裸官方接口

对照「自己拿官方 SDK 硬接」的基线，roost 多做了这些（面板「能力兼容说明」里也有）：

1. **被动回复窗口帮你管**：官方群聊 5 分钟 / 单聊 60 分钟、单条最多回 5/4 次。roost 按 msg_id 记账、数着次数，攒批超时或窗口过期自动降级到主动消息，而不是静默失败。
2. **攒批合并，回复更像人**：对方连发几条先等一下（2.5/5 秒，上限 8/15 秒）再一起回，不刷屏，也避开短窗口。
3. **投递账本**：每条回复进账本，能查到底送出去了还是卡在重试——官方接口本身不告诉你这条到没到。
4. **断线自动补拉**：SSE 事件流带序号，重连按 since 补拉；网关没起来时消息先排队，连上再补发。
5. **openid 映射成数字号**：把官方 openid 映射成整数号（真号优先、否则稳定合成号），大肥鱼的内存、@ 识别、会话键才能照常工作——这是兼容层的核心价值。
6. **凭据与权限守门**：面板密钥、SSRF 防护、来源校验都在 roost 这层；非本机的兼容端口默认要显式放行才监听。

## 能力边界（装之前先看）

| | 数量 | 例子 |
|---|---|---|
| 支持 | 15 | 收发消息、撤回、群信息、单成员禁言、进群审批、发图 |
| 降级 | 12 | 群成员列表（只列说过话的）、`get_msg`（最近 500 条）、发语音（要装 silk-wasm） |
| 不支持 | 15 | 拍一拍、合并转发发送、好友列表、全员禁言、改群名片/群名/头衔、拿 Cookie |

几个要注意的坑：

1. **群聊身份是合成号**。官方接口给 openid，兼容层映射成数字号：私聊能用真 QQ 号（主人识别正常），群聊其他人多是合成号。依赖真 QQ 号的人物记忆、@ 识别、按 QQ 号的白名单在群里会失真。
2. **被动回复窗口很紧**。官方群聊 5 分钟 / 单聊 60 分钟、单条最多回 5/4 次。大肥鱼的攒批（2.5/5 秒，上限 8/15 秒）和多轮回复容易耗光窗口。
3. **部分 OneBot 专属玩法没有**。拍一拍、合并转发发送、好友列表、空间、收藏到 QQ 等不可用。
4. **改头像 / 昵称 / 简介要先登录开放平台**。这些走开发者后台 CGI，不是 OneBot 能力；扫码建机器人只给凭证，不等于登录态。
5. **独占模式二选一**。设成 exclusive 时消息不进 roost 自己的插件管线，roost 的 dsh-roost 不能再回话；要两边都回用 parallel（可能重复）。

## 绑定 QQ 号：认人 + 接回旧记忆（建议做）

官方接口只给 openid、不给 QQ 号，所以兼容层默认把群友映射成**合成号**——大肥鱼认不出谁是谁，人物记忆、@ 识别、按 QQ 号的白名单在群里会失真。

解决办法有两条：

- **自助绑（推荐）**：主人先在 roost 面板「通知」页配好 SMTP 邮箱（启用开关、发件邮箱、SMTP 主机/端口、账号与授权码）。之后常用用户在群里发 `/绑定QQ <自己的QQ号>`，验证码会发到 `<QQ号>@qq.com`；再发 `/QQ验证码 <6位码>` 即完成。验证码只按发起人 openid 核销，拿别人的码也绑不上。roost 1.1.5 起独占模式也放行这些绑定命令。
- **主人代绑**：到 roost 面板「身份」页把 QQ 号 / 群号和 openid 绑定，或在群里用 `/绑定群号`、`/绑定成员 @某人 <QQ号>`。官方不给号码，只能本人或主人提供，模块不会替任何人猜。

绑定后的关键好处：**换机器人（换 AppID）后 openid 变了，记忆也能按号码读回来**——存量数据一个字节都不用动。就算你不换机器人，绑定也能让群聊里的记忆和 @ 识别对上真号。不绑定不影响收发，只是群里按合成号处理。

完整表在面板「能力兼容说明」页。

## 安全与审核声明

审核者重点看这几条，这里如实写清楚：

- **下载与联网边界如实说明**：模块胶水本身不下载、不执行远端代码：内置 roost 与 `ws` / `silk-wasm` 已作为普通文件打包在 `lib/vendor/roost/`，启动前只在本机整份复制到数据目录；模块自身对外的请求只有 `127.0.0.1` 上 roost 面板 API（含透传扫码），扫码协议由 roost 访问 `q.qq.com`，模块不接触。随包 roost 框架保留原版自更新能力：上游默认每 6 小时只**检查**新版本；本模块每次启动前会把运行配置的 `update.autoApply` 硬写回 `false`，只保留面板手动确认的更新路径，绝不在模块侧自动下载安装。用户手动确认时才由 roost 访问 `github.com` / `raw.githubusercontent.com` / `api.github.com` / `gitee.com`；发语音等场景还可能按 roost 面板配置的 npm 源（默认 `registry.npmjs.org`）装 `silk-wasm` / `@ffmpeg-installer`。这是内嵌框架的行为，不是模块胶水发起的。这份内置副本的来源锁定是 roost 1.1.7 / commit `69320e90…`（只用于审计随包版本），逐文件校验见 `lib/vendor/roost/SOURCE.md` + `SOURCE.sha256`，与发版逐字节一致、没有打补丁。**整个 `roost-bridge` 模块按 AGPL-3.0-only 授权**（见模块根 `LICENSE`、`module.json` 与 `lib/vendor/roost/LICENSE`），随包 `ws` / `silk-wasm` 依赖仍按各自 LICENSE。停用 / 卸载模块会延迟自动恢复网关（热重载不触发），但 DSH 进程直接退出无法保证，面板同时强提示先手动恢复。
- **凭据处理**：AppSecret、机器人 Token、roost 面板 accessKey、兼容层 token **只存本进程内存**，不写进模块数据目录、不回显明文（面板只显示「已暂存」）。唯一落盘的是 roost 自己 `config/bots/*.json` 里那份——那是 roost 的地盘。
- **不外发隐私**：不读取、不上传大肥鱼的聊天内容、记忆、Cookie。模块只调本机 roost 面板 API。
- **权限面**：所有面板接口带 `access: 'panel'`，复用宿主的回环 / 可信代理 / Host / CSRF 闸；模块不注册 QQ 命令，也不向模型注册工具，权限面只剩面板。扫码拿到的凭证先暂存内存，等 roost 停稳后写进配置并回读校验，不落模块数据目录、不回显明文。
- **capabilities 与实际一致**：模块胶水本身用 `network`（只调本机 roost API，含透传扫码）、`filesystem`（建模块数据目录、写 roost 配置）、`process`（起 roost 进程时调用 node）、`plugin-config`（`api.setConfig` 改网关）、`plugin-internals`（面板路由用 `api.core.http.body(req)` 解析请求体）。`dynamic-code` 来自随包内置的 roost 框架 / silk-wasm 依赖（插件加载器里的 `new Function`）；模块自己的代码不调用 `eval`，也没有子智能体委派。仓库校验扫整包源码，这两项按实际命中如实声明。

## 与 dsh-roost 的关系

如果机器上已经装了 `dsh-roost`，它自己也有「一键装 roost + 接好协议」的流程。这个模块面向**只用大肥鱼、没装 dsh-roost** 的用户，两者不要同时开兼容层的独占模式，否则消息只有一边会回。

## roost 进程的生命周期

模块起 roost 前先把 `lib/vendor/roost` 同步到数据目录 `roost-code`，再由 `lib/launch.mjs` 守护进程从那里拉起（`ROOST_HOME` 指 `roost-home`）。守护进程盯着宿主进程：**宿主真退出（正常关闭或崩溃）才收掉 roost**；模块热重载不换宿主 pid，不会把刚启动的 roost 误关。因为关 DSH 会停 roost，重开 DSH 后想让机器人自己上线，请打开设置里的「自动拉起」开关（默认关）。roost 自己的实例锁防止同一个机器人双开；手动停请用面板「关闭 roost」（走框架 `/api/shutdown`，会释放锁）。

## 故障排查

- 「模块自带的 roost 副本不完整」：安装包缺了 `lib/vendor/roost/src/main.js`，重装本模块。
- 「没装全局 Node，roost 会不会打不开」：不会。模块用宿主的 `process.execPath`，不查 PATH；桌面版 DSH 是 Electron 外壳时会自动加 `ELECTRON_RUN_AS_NODE=1`，让那个可执行文件按 Node 方式跑 `src/main.js`。点「一键诊断」能看到实际用的是哪个运行时。
- 「兼容模式需要 ws 依赖」：`ws` 随模块内置 roost 一起放在 `lib/vendor/roost/data/deps/ext/bundled/`，启动前会复制到 roost 数据目录的 `node_modules/`（市场打包器会跳过任何 `node_modules/`，所以源码里不能放那儿）。出现这条说明模块自带的 roost 副本缺文件，重装本模块。
- 「扫码后机器人没上线」：确认看到过「凭证已写入 roost，进程已重启」；这步会自动重启，不用再手动点。若没看到，重新扫码一次；再看开放平台是否开了「接收所有消息」、机器人有没有被拉进群。
- 「模块里填了 QQ 号，aurabot 里还是旧的」：模块里的 `selfUin` 只先写进 roost 兼容层；**要点「接入大肥鱼」**才会同步到 aurabot 顶层 `botQQ`。aurabot「连接」页的「用什么接 QQ → 接我已有的 OneBot 机器人」对应 `gateway:'onebot'`，接入时已经自动选好，不用手点；要改的是同一张卡片下面的「机器人 QQ 号」。aurabot 连上后会用 `get_login_info` 核对这个号，不一致会自己断开。点「一键诊断」能看到两边是否一致。
- 「配置好了但群里没反应」：① roost 建机器人后没重启；② aurabot 的 `botQQ` 还是旧号（重新点「接入大肥鱼」）；③ 开放平台没开「接收所有消息」；④ 机器人没进群；⑤ 网关改了但 DSH 没重启。
- 「重复回复」：兼容层模式设成了 parallel/mirror，改回 exclusive 并停掉 roost 那边的 AI。
