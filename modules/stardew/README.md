# 星露谷（stardew）

让鱼自己在《星露谷物语》里种田：**判断是她自己做的**，模组只负责把画面翻成文字、把她发的动作执行掉。

## 依赖的项目：必须先装游戏侧模组

这个模块只负责 aurabot 这一侧。**游戏里那个模组不在本仓库里，要去原帖下载**：

> **Blind Whale Farmer（大肥鱼种白饭）** — <https://github.com/Darianliu23/dsh-stardew-blind-whale-farmer>
> 作者：Darianliu23 · MIT · SMAPI 模组 + MCP 服务器

本模块**没有**打包它，也不镜像它的发布文件。原因很简单：模组是 C# / SMAPI 那套，
跟着游戏版本走、由原作者维护更新，放进来只会变成两份要同步的东西。

**装法（照原帖说明走）：**

1. 先装 [SMAPI](https://smapi.io)（开发时用的是 SMAPI 4.5.2 + 游戏 1.6.15）
2. 按原帖的说明把 `BlindWhaleFarmer` 放进游戏目录的 `Mods/`
3. 启动一次游戏，让模组把 MCP 服务器开起来（默认 `http://127.0.0.1:18080/mcp`）
4. SMAPI 控制台出现 `MCP 服务器已启动` 就算通了

游戏侧的配置（API Key、端口、`PauseWhenAiStops` 这些）都在 `Mods/BlindWhaleFarmer/config.json`，
原帖里有完整说明——**以原帖为准**，本文件只讲 aurabot 这边怎么接。

## 接口是怎么来的

本模块**基于原插件的 SMAPI 模组**开发，复用它的 MCP 协议与工具名（`get_state`、`water_crops`、
`harvest_crops`、`travel_to`、`update_notes`……），但**没有**复用它的 DSH 插件层。

原插件的 DSH 部分是「会话预设 + 入口工具」那套结构：开一个专有预设，新会话选它才连上游戏。
本模块按 aurabot 的模块接口重写了一遍，接法是「后台会话 + web 路由 + QQ 命令」：

| | 原插件的 DSH 层 | 本模块（aurabot） |
|---|---|---|
| 怎么进游戏 | 新建会话时选「大肥鱼种白饭」预设 | `/自己玩 10` 或面板按钮，模块自己起一个 `system:stardew` 后台会话 |
| 工具暴露 | 整个预设挂四十多个游戏工具 | 后台会话只挂 `stardew_game` 一个；私聊只留只读的 `stardew_peek` |
| 汇报 | 会话里直接说 | 用 OneBot 直发一条汇总（避开出站策略） |
| 起停游戏 | 手动开、按 F8 | 脚本自己拉起 `StardewModdingAPI.exe`、点存档、收工后 `sleep` 存档再关进程 |

所以游戏模组是**同一份**，只是上层接法不同。两边可以共存，但**别同时操作**：
按 F8 启动的模组内置 AI 会抢操作，模组会提示先把它停掉。

## 它在做什么

```
我（后台会话）──stardew_game 工具──> 模组 MCP（127.0.0.1:18080）──> 游戏里执行（寻路/浇水/钓鱼…）
        ↑                                                                    │
        └──────────────────── 文字状态（get_state）──────────────────────────┘
```

- 模组把画面翻译成纯文字（时间、体力、背包、坐标地图、作物、附近物体），**不需要视觉模型**；
- 鱼自己看状态、自己决定干什么，再发高层动作；
- 跑完整一局（几轮）以后只往私聊发**一条**总汇报。

## 怎么用

| 方式 | 说明 |
|---|---|
| `/自己玩 10` | 让她自己玩 10 分钟（只写数字；不写默认 30） |
| `/收工` | 叫停，这一轮做完就收 |
| `/星露谷` | 查连通性（游戏开着没、MCP 通没通） |
| 私聊里 `stardew_peek` | **只读**：问「农场怎么样了/笔记写了啥」看一眼，不会动手 |

## 一轮只干一件事

这是踩出来的规矩，写死在提示词里：一轮只允许做一件原子动作（浇完这一片 / 收一次这一块 /
走回屋子），做完立刻收尾。

为什么：单轮预算 9 分钟时，一轮里塞两三件事，光 `get_state` 就要几十秒，剩下的做不完，
时间一到就被硬断——实测 12 分钟只跑成 1 轮。改成一轮一件之后：**6 分钟跑 8 轮，每轮 30-40 秒，
全部无超时**。

## 每轮带回一句自己的话

后台那轮模型的最后一步常常还在调工具，返回的正文是空的，汇报里就只剩「跑了 N 轮」。
所以提示词里明确要求：写完 `update_notes`，最后一步只说话、不调工具；模块再用 `voices[]`
把每轮那句攒起来，汇报里逐条列出：

```
【星露谷】玩了 6 分钟，跑了 8 轮，已存档、游戏关掉了。

第1轮：这一轮就做了一件事：把农场上那 12 株蓝莓一次全收完了，一按就全收了，挺痛快的
第2轮：这轮只干了一件：去农场把 12 株作物全浇了，体力还剩 248。就是背包只剩 3 格，一堆垃圾占地方，有点烦
第3轮：这轮把背包里的蓝莓全放进出货箱了：32 个普通的、1 个银星、3 个金星，今晚能结算约 1900g
```

## 设计上刻意做的几件事

1. **玩游戏的活儿只在后台会话（`system:stardew`）里干**。那个会话只挂 `stardew_game` 一个工具，
   人格还是全局那份，所以「还是她」，不是另一个 AI。私聊里不挂完整工具，避免她手痒自己开一局。
2. **汇报只发一条，且用 OneBot 直发**。早期用 `pushToSession` 会往会话塞"用户消息"，她得再想一轮，
   排队久了汇报会积压、时间线倒序；用 `api.sendText` 又会被出站策略当主动发言拦掉。
3. **只看硬证据**：存档是否真的更新（比 `Saves/<存档>/<存档>` 的 mtime）、游戏进程是否真的关了、
   模组 MCP 是否真的通了。后台那轮模型的自述只作参考——它会瞎编过程。
4. **自己起游戏、自己关游戏**：`stardew-launch.ps1` 负责拉 `StardewModdingAPI.exe`、抢窗口前台、
   按比例坐标点「加载」和存档行；收工后 `sleep` 存档再关进程。

## 设置项

| 键 | 说明 |
|---|---|
| `port` | 模组 MCP 端口，和模组 `config.json` 的 `McpPort` 一致，默认 18080 |
| `gameDir` | 有 `StardewModdingAPI.exe` 的那个文件夹 |
| `timeoutMinutes` | 单个动作最多等几分钟（钓鱼、下矿很长） |
| `selfPlayGapMin` | 自己玩时两轮之间歇几分钟 |
| `allowOthers` | 允许群聊/别人用只读工具（默认关） |

## 已知坑（都踩过并修了）

- **SMAPI 不热加载模组**：装完必须重启游戏，否则 MCP 端口不通。
- **游戏停在标题画面**：MCP 已经在听，但 `get_state` 会回「游戏还没有进入存档（在标题画面或正在加载）」。
  判断进没进存档要匹配这句原文（少一个字就会永远判错，之前就是这么假成功的）。
- **`pauseWhenOutOfFocus`**：游戏设置里这项开着时，窗口被别的程序挡住会整个冻结，看着像在玩其实时间不动。
  本模块装好后请把它关掉（游戏设置 → 「窗口不活动时暂停」）。
- **模组 `PauseWhenAiStops`**：同理，介意的话在模组 `config.json` 里设成 `false`，并把 `McpIdleSeconds` 调大。
- **按 F8** 启动的是模组自带的 AI，和本模块抢操作，会提示先停掉它。
