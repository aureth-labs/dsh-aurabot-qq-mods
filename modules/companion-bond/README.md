# 相伴养成

给正在 QQ 里和你聊天的 Aurabot 增加相处进度。聊天、喂她吃饭、陪她玩和摸摸，都能逐步积累亲密度与经验；她在后续聊天中会知道当前的相处状态，并沿用已有的人格作出回应。

## 怎么玩

默认只统计**插件配置中的主人与她的私聊**。不需要领养或创建新角色。

| 在 QQ 私聊发送 | 效果 |
| --- | --- |
| 平常聊天 | 每次有效聊天 +1 经验、+1 亲密度 |
| 陪你玩 / 一起玩 / 玩耍 | 玩一会儿，增加愉悦，消耗 12 精神 |
| 摸摸你 / 摸摸 / 抱抱 | 增加愉悦与亲密度 |
| 晚安 / 去休息吧 | 开始休息，精神每小时恢复 12 |
| 早安 / 起床啦 | 结束休息，不会瞬间回满精神 |
| 养成状态 / 亲密度 | 查看等级、阶段、精神和亲密度 |
| 养成帮助 | 查看玩法 |

自然互动会继续交给机器人原有的聊天流程，由她用平常的口吻回应。模块自身不额外发起模型请求。模型是否自然表现出状态仍受所用模型和原有人格影响。

精确命令也可以用：`/养成 状态`、`/养成 玩耍`、`/养成 摸摸`、`/养成 休息`、`/养成 起床`、`/养成 帮助`。这些命令直接返回操作结果和状态。`/相伴` 是别名。

“陪你玩”这类短语按整句匹配；讨论“怎么写一个陪你玩的模块”等普通句子不会触发玩耍。

## 喂饭沿用已有模块

兼容本机已安装的 **feed（喂食）3.2.0** 导出接口 `state().log`，不修改它的源码、设置或存档。以后 feed 更改该接口时可能需要适配。

- 仍然使用原来的投喂面板、自然语言投喂，或 `/喂食 小蛋糕 甜 一份`。
- 本模块每 15 秒检查一次实际记录，聊天和查看状态时也会同步。
- 记录标为“投喂”且实际饱食增量大于 0，才算一次投喂成长；吃不下、自己找零食不计入。
- 同一条记录不会重复加分，重启后也不会重复。
- 从本模块首次创建存档之后开始统计；此前的喂食历史与 feed 原有好感度保留原样，不折算为新的亲密度。
- 投喂归属沿用 feed 模块的“投喂”标记。本模块不自行判断或重新执行投喂。
- feed 未启用时，聊天、玩耍、摸摸和休息仍然可用。

## 成长规则

| 行为 | 经验 | 亲密度 | 奖励间隔 | 每日奖励上限 |
| --- | ---: | ---: | --- | ---: |
| 聊天 | +1 | +1 | 默认 30 秒，可设置为 0 | 默认 60 次，可配置 |
| 实际投喂 | +8 | +5 | 30 分钟 | 4 次 |
| 玩耍 | +6 | +4 | 10 分钟 | 6 次 |
| 摸摸 / 抱抱 | +2 | +2 | 5 分钟 | 12 次 |
| 休息 / 起床 | 0 | 0 | 只切换状态 | 无奖励 |

普通互动可以同时获得一份聊天奖励和对应行为奖励。状态、帮助和斜杠命令不算普通聊天。重复收到同一个消息编号会去重。

冷却和上限只限制成长奖励，不影响正常聊天。若想每说一句都计分，可以把“聊天成长间隔”设为 0。每日上限在**北京时间零点**更新。

亲密度上限为 1000，依次进入：初识（0）、熟悉（30）、亲近（100）、默契（250）、深厚（600）。等级由累计经验决定，达到下一等级所需累计经验为 `25 × 当前等级²`。

醒着时精神每小时减少 2，最低 20；低于 35 或正在休息时不能获得玩耍奖励。愉悦随时间缓慢回到 60。离线同样按实际经过的时间计算；长期不来不会扣亲密度。

## 面板与设置

Aurabot 面板中新增“相伴养成”标签页，可以查看进度、近期互动并点击“陪她玩”“摸摸”“让她休息”。面板互动只更新养成状态，不主动发 QQ 消息；她会在后续聊天时感知状态。

“在群里也启用主人养成互动”默认关闭。开启后，主人 @ 她的消息才参与自然互动；其他成员不能操作。群内使用状态查询会让群友看见相处数值。该设置不改变机器人原有的群聊回复策略。

喂食本身造成的饥饿和心情变化继续由 feed 负责。玩耍、摸摸若检测到内置 mood 模块，会轻微推动心情；没有 mood 也能运行。

## 安装

需要 Aurabot **1.2.1 或以上**，扩展接口 v1；无需安装 npm 依赖。

本模块的发布包内 `module.json`、`index.mjs`、`panel.js`、`lib/` 等应处于压缩包根目录。支持导入模块 zip 的插件版本可从文件安装；否则把整个 `companion-bond` 文件夹放入插件数据目录的 `modules/`，保存后由插件自动加载。

停用可在“已安装”页关闭“相伴养成”。存档保存在 `modules-data/companion-bond/state.json`；停用、升级模块或重启应用不会清除它。请勿在插件运行时手工编辑存档。

## 文件与权限

- `filesystem`：仅在本模块自己的数据目录写入存档，先写临时文件再原子替换。存档损坏会报错停下，不会静默重置覆盖。
- 存档包含数值、时间、近期互动类型和去重键，不保存聊天正文、QQ 号或 Cookie。投喂去重键为哈希值。
- 通过公开模块 API 读取 feed 导出，调用可选 mood 导出，并为主人的正常聊天补充约数百字的状态背景。没有单独模型调用，但补充背景会略增正常聊天的输入 token。
- 不直接访问外部网址，不新增网络请求，不运行其他程序，不读写插件全局配置。
- 不设置主动发消息任务。原有 feed 模块已有的零食、喊饿及模型调用仍按其自身设置运行。
- 自定义面板使用插件已提供的 React 与组件，不加载外部资源。

## 开发与测试

`node --test test/*.test.mjs` 验证计分、冷却、去重、跨日、休息恢复、存档及模块事件行为。发布包不含测试。

提交模块市场时，将整个源码文件夹放到市场仓库的 `modules/companion-bond/`，运行 `npm run catalog`、`npm run check`、`npm run pack` 后，以单模块 PR 提交。模块市场的审核与发布由仓库维护者执行。
