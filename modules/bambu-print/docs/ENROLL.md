# 登录：账号密码不进聊天

**结论**：现在登录 Bambu 云端不用在聊天里发密码。你私聊发 `/打印机 登录`，机器人回一条网页链接；你在网页里填账号密码，网页在你的浏览器里加密成一段 `BBX1.…`；你把这段贴回私聊，机器人用私钥解开、登录、把 token 加密存起来。一段只能用一次，网页上固定 10 分钟内有效。

这套流程叫「离线信封」。格式和安全设计在 [ENVELOPE.md](ENVELOPE.md)，这里只讲为什么改、怎么用、边界在哪。

## 1. 旧流程的问题

旧流程是 `/打印机 登录 <Bambu账号> <密码>`。三个问题：

1. **账号密码直接进聊天**。聊天记录是明文留存的：QQ 服务器、备份、同步盘、任何能看到历史的人都能看到。私聊也一样。
2. **撤回不可靠**。代码里已经把「撤回消息」整个删掉了（`index.mjs` 有注释说明原因：机器人撤自己的消息经常没权限，而且那句「我撤回了」本身又提醒大家这里有敏感消息）。所以别指望发完再撤回。
3. **泄露是永久的**。一段明文账号密码，能用到你改密码为止；被人翻到几年前的记录也能用。

现在这条旧命令已经不能用了：带参数时，机器人只把后面的内容当信封解析，不是 `BBX1.` 开头就回「这段不像是这台机器生成的登录信封（应该以 `BBX1.` 开头）」。**注意**：它不会把后面那串当账号密码用，但你已经发出去的那句话仍然留在聊天里。照着旧帮助发，是最容易踩的坑。

## 2. 改成什么样

| | 旧流程 | 现在 |
|---|---|---|
| 密码在哪出现 | 聊天记录里，明文 | 你的浏览器内存；机器人进程内存（解密后交给登录，最多几分钟） |
| 聊天里留下什么 | 账号 + 密码 | 一段密文 |
| 能用几次 | 无限次 | 一次 |
| 有效多久 | 永久 | 10 分钟（从网页生成那一刻算） |
| 谁能解开 | 任何看到记录的人 | 只有这台机器的私钥 |
| 泄露之后 | 账号被接管 | 一段最多再用一次的密文（10 分钟内，而且别人先用掉就作废） |

代价也要说清楚：多了一步「打开网页、复制、粘贴」；网页打不开就没法登录；密文如果先粘到别处（笔记、文件传输助手），它仍然只能用一次，但多躺了一份，尽量直接粘回私聊。

## 3. 你实际会走一遍

1. **私聊**发 `/打印机 登录`（群里发会被拒；前提是你在宿主的私聊白名单里）。第一次用也能直接发，不需要先有账号或先解锁。机器人回一段说明，里面有：
   - 一条链接，末尾是 `#k=<87 个字符的公钥>`；
   - 一行「公钥指纹 xxxxxxxx」，意思是页面打开时会显示同一串，对上了才是发给这台机器的。
2. 点开链接，页面「第一步：确认公钥」会显示「公钥指纹 xxxxxxxx」。要和机器人私聊里发你的那串一模一样；**对不上就别填**，回私聊重新要链接。
3. 在「第二步：填账号和密码」里填 Bambu 账号：邮箱，或 5~15 位数字的手机号。再填密码（可以点「显示」核对）。区域默认「中国大陆」，国际站账号（邮箱常见 gmail / outlook）要改成「国际」或「欧洲」，选错会登录失败。
4. 点「生成加密文本」。加密在浏览器里完成，不会发网络请求。成功后输入框会自动清空，页面出现「第三步：把这段发回私聊」，里面有一段 `BBX1.…` 和一行「某年某月某日某时前有效，且只能用一次」。
5. 点「复制整条命令」。它已经带上了 `/打印机 登录`，回私聊直接粘贴发送就行（也可以只复制密文，自己加命令）。
6. 机器人回「登录成功（账号密码没有进聊天记录），云端 token 已加密保存」，后面跟发现的台数和名字。新用户会在这一步自动建号，不需要先设任何东西。
7. 回到 `/打印机 状态` 就能用了。

页面不保存任何输入（没有 localStorage、没有 cookie），关掉就没了；换台设备打开要重新填。

## 4. 云端要验证码或两步验证

有些账号光有密码不够：

1. 机器人会回「云端要求验证码」。先发 `/打印机 验证码`，让云端把码发到账号的邮箱或手机。
2. 收到后发 `/打印机 验证码 <6位>`。
3. 如果回的是「云端要求两步验证」，就在验证器里看 6 位码，发 `/打印机 两步验证 <6位>`。

这条登录会话只在机器人内存里留 5 分钟，超时要重新走一遍登录。密码和验证码都不会写到磁盘上。

**OAuth 注册的账号**（用 Google / Apple 登录建的号）没有密码，要先去 Bambu 手机 App 里设一个：Account Security → Change Password，之后才能用这条流程。

## 5. 网页那份代码在哪

全在 `assets/enroll/`，是纯静态文件（没有构建、没有第三方依赖），原样拷到任何静态托管就能用。默认那份在 GitHub Pages 上，地址见第 6 节。

| 文件 | 作用 |
|---|---|
| `index.html` | 唯一页面：取公钥、填表、生成、复制 |
| `bbx.js` | 信封加解密的唯一实现，浏览器和 Node 共用；服务端也 import 它 |
| `enroll-form.js` | 校验和组装明文，纯函数，可在 Node 里单测 |
| `style.css` | 样式 |

几条硬约束（测试会盯着）：

- 没有构建步骤、没有第三方依赖、不引用任何外部域名、不发 fetch / XHR / WebSocket。
- 不写 localStorage / sessionStorage / cookie / indexedDB。关掉或刷新就丢。
- 优先从 `location.hash` 的 `#k=` 取公钥（hash 不会发给服务器），没有再读 `?k=`；也接受整条链接粘贴。
- 生存时间固定 10 分钟，页面上不给改；区域默认中国大陆。
- 结果区标题是「第三步：把这段发回私聊」，写着「只发私聊，不要发群里」；下面是密文和两个复制按钮（「复制整条命令」「只复制密文」）。

## 6. 链接从哪来，会不会被换成别人的页面

机器人发的是 `enrollService.link(settings().enrollBaseUrl)`，也就是「前缀 + `#k=<公钥>`」。

- 设置项 `enrollBaseUrl` 留空时，用代码里的默认值 `https://cdcp998.github.io/dsh-aurabot-qq-mods/`。这是本仓库的页面，只有仓库维护者能改。
- 别人 fork 之后应该把 `enrollBaseUrl` 改成自己部署的那份。否则用户点开的是别人的页面。页面只能加密、拿不到私钥，但能偷用户在页面里填的明文。
- 机器人只校验前缀是 `http://` 或 `https://`、长度小于 300 个字符，**不会去请求它**。地址不合法时，聊天里只会得到一句「登录链接还没就绪，稍后再试」。
- 面板「登录信封」页能看到当前链接、公钥指纹、已用掉几段；还能贴一段进来「解析」，只解不消费、账号打码，用来确认复制对没对。注意这是给主人看的页面，`enrollBaseUrl` 本身不在面板「设置」页里（见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 6 节）。

## 7. 静态网页的可信边界

这段最重要，别跳。

**它能保证的**：

- 页面只有公钥，只能加密；没有私钥就解不开你生成的东西。
- 私钥在机器人的数据目录里（`bbx-key.json`，0600），不会返回给面板、不会进聊天、不会进日志。
- 密文只能用一次、会过期（细节见 [ENVELOPE.md](ENVELOPE.md)）。
- 审计只记动作和结果（`register` / `envelope` / `login`），不写账号和密码。

**它保证不了的**：

- **谁控制页面，谁就能在你加密之前偷走账号密码。** 公钥加密解决不了「页面本身是假的」。所以：核对指纹，或者把 `enrollBaseUrl` 换成你自己部署的页面，二选一。
- **能读数据目录的人能解开在途信封，也能解开所有凭据。** 私钥和保险箱在同一个目录。这条挡的是「事后翻聊天记录」和「备份被拷走」，不是「本机管理员」。
- **挡不住运行期间 dump 进程内存。** 私钥、明文、token 都在同一个进程里，能读内存的人不需要走信封。
- **挡不住改代码。** 改一行就能在解密那一刻把明文抄走。任何在本机解密的方案都一样。
- **挡不住你把密文粘到别处。** 它仍然只能用一次，但多躺一份就多一份被翻到的机会。

一句话：这套东西把「泄露的东西」从「永久有效的明文密码」换成了「一段十几分钟内作废的密文」。它没有让机器本身变得可信。

## 8. 私钥放哪，能不能更严一点

默认：`bbx-key.json` 放在数据目录里，0600，首次用到时生成。这是 `keyMode: 'file'`。

信封服务的构造函数还支持两种更严的形态，但**面板和命令都没有入口**，只有直接改代码或部署参数才能用：

| 形态 | 私钥在哪 | 重启后旧链接 | 事后拿到数据目录，能解在途信封吗 |
|---|---|---|---|
| `file`（现在的默认） | `bbx-key.json` | 还有效 | 能 |
| `ephemeral` | 只在进程内存 | 失效，要重新拿链接 | 不能；启动时会删掉上一任留下的 `bbx-key.json`，删不掉就报 `IO`，信封功能不启用 |
| `keyPath` | 你指定的绝对路径（加密卷 / systemd credentials / 容器 secret 挂载） | 看那个文件在不在 | 看那个文件有没有被一起拿走 |

`keyPath` 和 `ephemeral` 不能同时设（会报 `BAD_INPUT`）；`keyPath` 只接受绝对路径，不支持「从网上拉一把私钥」。

想换一把私钥：代码里有 `envelope.rotate()`，会换钥并清空已用记录，但**没有路由也没有按钮**，所以现在没有「重置密钥」这个操作。删掉 `bbx-key.json` 再重启也会生成新钥，但已用记录不会跟着清（旧的 jti 留着无害）。

## 9. 关于「安全码」

旧文档里那套「每人设一个安全码、用安全码解锁」已经整体取消。现在所有账号都由这台机器的 `host-key.bin` 包着 DEK，登录完直接能用；`/打印机 解锁`、`/打印机 设置安全码 …` 这类老命令只会回一句「安全码已经取消了」。为什么这么改、代价是什么，写在 [ARCHITECTURE.md](ARCHITECTURE.md) 第 2.2 节，这里不重复。

## 10. 失败了看哪里

机器人回的话基本能直接照着做：

- 「这段信封已经用过了」：重新生成一段。一段只能用一次。
- 「信封过期了」：重新生成。网页固定 10 分钟，别生成完先去干别的。
- 「这段信封解不开」：可能不是给这台机器的，也可能复制时少了字符。重新复制整段。
- 「这段不像是这台机器生成的登录信封（应该以 `BBX1.` 开头）」：没复制全，或者还在用旧的「账号 密码」写法。
- 「登录密钥还没就绪」：让主人在面板「登录信封」页看一眼，通常是数据目录不可写。
- 「登录失败：Bambu 账号或密码不对」：密码错，或者这是 OAuth 账号还没设密码，重发 `/打印机 登录` 拿网页链接再试。

每个错误码的含义见 [ENVELOPE.md](ENVELOPE.md) 第 9 节；面板接口的返回格式见 [ROUTES.md](ROUTES.md)。
