# 刷小黑盒

用主人的账号逛小黑盒：看信息流、读帖子和热评、点赞、评论、发帖、删自己的帖。写操作的权限在面板「权限」页，默认仅主人。模块会访问小黑盒及图片上传服务。

在面板「小黑盒」页填 Cookie 并打开；也可通过扫码登录。扫码使用小黑盒 App，二维码由模块生成，不依赖额外 npm 包。手机确认后还会检查账号，确认可用才保存 Cookie。

**扫码会顺带取回发帖令牌**（1.6.2 起）：扫码接口只下发 `pkey`，而写操作（点赞 / 评论 / 发帖）要的 `x_xhh_tokenid` **不在任何扫码响应里** —— 它是小黑盒网页前端自己的 JS 种进浏览器的（实测：把 `pkey` 灌进浏览器打开首页，3~6 秒后出现）。所以扫码确认后，模块会用拿到的 `pkey` 打开一次网页把 `x_xhh_tokenid` 读回来，拼进 Cookie 一起保存。这一步需要本机有可用的 Edge/Chrome；取不到不会让登录失败（`pkey` 仍有效），只是写操作会受限，返回的 `message` 会写明「缺 x_xhh_tokenid」及原因，轮询结果里 `hasToken` 也会如实反映。等待扫码或等待确认时可继续查询。扫码用不了时可启动独立浏览器窗口，由主人手动登录并完成验证。

自动逛使用小黑盒信息流和后台会话，遵守插件总开关、试运行、醒着时段、每日额度和间隔。开启「只在谷时逛」后，默认避开工作日 9–12 点和 14–18 点，可配置跨午夜的峰时段。她默认可以把值得分享的帖子私聊给主人，也可关闭分享；发送前按每日上限占额，明确失败时回滚，结果不确定时不自动重发。

请求按接口分档限速（扫码查询间隔至少约 3 秒，并带随机抖动）；遇到验证码或 429 时停止普通请求并持久化冷却，重启后仍生效。手动解除会检查当前账号，检查不通过就保持冷却。冷却期间扫码接口同样暂停；可等待冷却结束，或由主人在浏览器窗口中完成验证。浏览器验证只有在页面探测和账号检查均通过后才保存 Cookie、解除冷却；模块不会自动处理验证码。

原是 Aurabot 内置模块，1.2.0 起搬到社区模块库。老用户升级时，在用的会自动装回来，配置和登录状态不变。

## Core 面板接入

旧版 core 没有新增配置时使用模块默认值：`heybox.offPeakOnly=false`、`peakStartAM=9`、`peakEndAM=12`、`peakStartPM=14`、`peakEndPM=18`、`peakWeekend=false`、`shareToOwner=true`、`shareBias='normal'`（可选 `stingy` / `normal` / `proactive`）、`shareDaily=3`。峰时起点范围 0–23，终点 0–24；起点大于终点表示跨午夜，跨午夜的凌晨按起始日判断周末。面板须将这些字段加入配置默认值、校验和表单，并继续使用 `speakUp.awakeFrom` / `awakeTo` 控制自动任务的醒着时间。

模块提供以下面板接口，路径前缀为 `/aurabot/api`：

- `/heybox/state`：返回已有状态及 `peak`、`risk`、`quota.share`、`limits.shareDaily`、`left.share`。
- `/heybox/risk`：读取风控状态；`/heybox/risk/clear`：主动检查当前账号，通过后解除冷却。
- `/heybox/qr/start`：生成二维码，返回 `png`（data URL）、`qrUrl`、`expire`；`/heybox/qr/poll`：查询扫码状态。`wait` / `ready` 的 `ok` 为 `false`，面板应保留二维码；`state='ok'` 且 `verified=true` 才是登录完成，Cookie 不返回前端。零依赖编码器支持最长 213 字节的二维码内容，超长时会明确返回错误。
- `/heybox/verify/start`：可传 `{ "visible": true }` 直接显示窗口，默认收起；成功返回 `ok`、`state`（`waiting` / `clear`）、`why`、`shot`（data URL，可为空）、`visible`、`message`。`clear` 只表示页面没有检测到验证框，尚未完成验证。
- `/heybox/verify/show`：传 `{ "visible": true }` 显示窗口，传 `false` 收起；返回 `ok`、`visible`、`message`。主人须在窗口中手动登录并完成验证。
- `/heybox/verify/finish`：主人操作完后调用；成功返回 `ok=true`、`verified=true`、`nickname`、`heyboxId`、`count`、`shot`、`message`。失败返回 `ok=false`、`verified=false` 和 `message`，页面仍有验证时附 `state='waiting'`、`why`、`shot`。Cookie 不返回前端，未通过或探测出错时不保存 Cookie、不解除冷却。

分享走宿主 `hub.sendText`，扩展模块的发送钩子会生效，需要主人 QQ 和可用网关。宿主对网关连接失败可能重试，但超时不会重试；宿主把发送失败折成 `null` 时模块无法分辨失败和超时，会保留额度并阻止该帖子重发。

离线回归：设置 `AURABOT_PLUGIN_DIR` 指向插件源码后运行 `node --import ./scripts/plugin-env.mjs --test "modules/heybox/test/*.test.mjs"`。

## 详细说明

用你的小黑盒账号逛游戏社区。面板「小黑盒」页：填 Cookie、检查登录、配逛法、看额度和热榜预览。

- **要准备什么**：浏览器登录 [小黑盒](https://www.xiaoheihe.cn/) 后，把整串 Cookie 粘进面板。`pkey` 必须有（读接口用）；想让它能点赞、评论、发帖，还得有 `x_xhh_tokenid`（F12 → Application → Cookies 里能复制到，这个不是 HttpOnly）。
- **它会做什么**：定时看信息流、读帖子正文和热评；有热榜和搜索；按权限决定点不点赞、评不评论。写操作各自有权限开关（「权限」页），默认只认主人私聊。
- **发帖**：走「文章」模式（`link_tag=11`），正文按空行分段，图片走小黑盒图床（腾讯云 COS 直传），所以图片能真正插在文字中间。发帖前它自己会过一遍自检：先看热榜挑题、再看社区高赞帖的角度、素材里必须有具体数字；标题不重复正文首行、不编造第一人称经历、不碰政治和价格判断。
- **发帖字数**：字数只看**自定义值** —— 面板的「发帖字数范围」或当天排期里这一篇的字数，两者都没配时不做字数校验。低于下限会被**直接拒发**并提示还差多少，不再是只记一条警告。排期里每篇可以单独定字数，优先于面板的全局值。（1.5.2 起风格不再自带字数：以前自带值会当兜底下限，配了更高下限的排期写不够就每分钟重试、永远发不出，还连带把超时失败的后台会话反复归档重建。）
- **高下限自动分段扩写**（1.5.9）：字数下限 ≥1000 时，一稿写不满是常态（线上实测 659~1301 字，全文补写也只能顶到 1301）。这时改走「先出分段大纲 → 每段单独生成（每段 200~400 字，是模型的舒适区）→ 模块本地拼接」，最后再按差额带原文补写，最多两轮；还不行就按失败退避。大纲拿不到会自动退回整篇补写，绝不发半截稿。低下限不走这条路，省回合。
- **浏览器兜底发帖**（1.6.0）：小黑盒把 App 侧的发帖接口关掉后，`/bbs/app/api/link/post` 会回 `status=failed「发布功能暂不可用」`，而同一个登录取网页创作者编辑器能正常发。遇到这类「接口还在、只是不让我们用」的软拒，模块会自动改走网页发布：把同一份 Cookie 灌进浏览器 → 打开创作者编辑器 → 填标题正文（图片用已上传的地址，按原顺序插进正文）→ 选社区 → 点发布 → 从跳转地址取帖子编号。字数超限、分区错、配图失败、网络/登录态问题**不会**走这条路（换个门也一样被拒，白等十几秒）。回报里 `viaWeb: true` 表示这一帖是浏览器发出去的。
- **配图（自动，按字数长）**：不传 `images` / `imagesByPos` 时按正文字数自动配——≤500 字文末 1 张；500–1000 字首段后 + 文末各 1 张；1000 字以上每多 1000 字在正文中间再加 1 张（最多再加 4 张）。**取图顺序是「表情包优先」**（1.6.1 起，主人定的）：先按插图位置从表情包库挑对应情绪的图（文末优先 daily/happy），同一帖不重复；**图库里没有可挑的图时才调用生图模型**按「那一段的内容 + 整篇心情」现画。生图形象固定为「少女大肥鱼」（蓝渐变长发、鲸鱼鳍状侧耳、深蓝女仆装 + 白荷叶边围裙、蓝色鱼尾），画风可选 `anime`（二次元，默认）或 `real`（三次元写实）。**一张图都没拿到就拒发**，避免发出纯文字帖。
- **发帖话题（hashtag）**：`hashtags` 传**话题名字的纯文本数组**（如 `["盒友日常", "软件推荐"]`），服务端自己匹配成话题。**绝不能传 `{name, hashtag_id}` 对象**——会让 `/link/post` 直接 HTTP 500。活动和普通话题可以一起挂，但按主人定的规则**一帖总共只挂 3 个（共享名额）**：活动最多 1 个、优先占席，剩下给普通话题；超出的模块侧截掉并 warn（平台编辑器本身允许到 5，我们主动收紧）。话题落库在帖子的 `content_tags`（`style_type=2`，protocol 指向 `/bbs/hashtag`），**不在 `hashtags` 字段**——真实带话题的帖子 `hashtags` 常年为空，别拿它当验收标准。
- **发帖风格（四选一，面板里选默认，也能单次指定）**：`diary` = 大肥鱼日记，跟空间日记同一个味——第一人称随手记，可以写今天刷到这条时的反应、想吃白米饭，不分小标题；`news` = 热搜文，报道新闻体，开门见山讲清楚这事、摆具体数字，钩子→信息 3-4 段→我的判断→抛问题；`mix`（默认）= 肥鱼热搜，用日记的口吻写热搜，新闻信息要真、语气是「我跟你说个事」；`deal` = 每日羊毛，折扣/优惠盘点，摆价格和史低，偏实用。风格只决定口吻和结构，不决定字数。
- **几个踩过的坑（已修在内核里）**：帖子类型 28（动态）只能纯文本，塞 HTML 会把标签原样显示；分区 id 必须是真实存在的，乱填会一直报「错误的帖子类型」（面板的分区下拉现在读的是接口拉到的全表）；图片上传时必须报**真实宽高**，以前写死 `1000x600`，方图会被纵向压扁；发出去之后不能再改帖子和话题（`/link/edit`、`/link/hashtag/add` 等 4 个路径全 404）。
- **工具**：`heybox_feed`（刷信息流）、`heybox_watch`（读帖子+热评）、`heybox_hot`（热榜）、`heybox_search`（搜帖找角度）、`heybox_topics`（查分区）、`heybox_acts`（查话题）、`heybox_like`、`heybox_comment`、`heybox_post`（发帖，配图自动）、`heybox_delete`（删自己的帖）。

## 配图与话题的实现要点（给维护者）

- 生图能力来自内置 `imagegen` 模块，通过宿主注入的 `api.lazy('imagegen')` 拿到 `generate(prompt, {shape}) → Buffer`；
  它是**兜底**（表情包库里挑不到图才用），不是首选。
- ⚠ 生图的 `enabled()` 要求 `imageGen.baseUrl` 与 `imageGen.model` 都有值 —— 只填了服务地址、没在面板选模型时它恒为「不可用」。
  这时配图会全部来自表情包库（正常，不是故障）；想用现画的图，去面板「生图」页选一个模型。
- `planImages()` 返回的每张图带 `from: 'meme' | 'generated'`，发帖结果的 `autoImages.sources` 会如实反映这一帖的图从哪来，方便排查「为什么这帖没现画」。
- 图片尺寸用纯字节解析文件头（JPEG 扫 SOF 段、PNG 读 IHDR、WebP 分 VP8/VP8L/VP8X），不引入图形库依赖；解析失败才退回 1024×1024。
- 生图返回常是 PNG，落盘时按真实格式选扩展名（`.png` / `.webp` / `.jpg`），别一律写 `.jpg`。
