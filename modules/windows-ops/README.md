# 逛电脑（windows-ops）

经 PowerShell 操作主人这台 Windows 电脑：窗口枚举/激活/关闭、全屏截图、剪贴板读写、键鼠模拟（移动/点击/打字/按键），
以及 **UIA 元素定位**（读无障碍树，按选择器精确操作控件）。

v1.3.1 起还多了两件「隔着 QQ 用这台电脑」的事——都走 **机器人自己的 QQ 客户端内建功能**，不再截图发帧、也不自建网页：

- **屏幕共享**：在机器人 QQ 的聊天工具栏点「屏幕共享」→「选择你想共享的窗口」里选「桌面」→「确定」；
- **远程协助**：点「远程协助」右侧箭头 → 菜单「邀请对方远程协助」，对方在 QQ 里接受后直接看屏并操作鼠标键盘。

v1.3.2 给这两件事加了 **发起前截图确认**：真正点 QQ 按钮前，先把当前屏幕截图发到主人私聊，主人回「确认」才发起（见下文「发起前截图确认」）。

两者默认发给主人；主人也可以指定机器人好友列表里的某个好友（见下文「按主人指令指定好友」）。

## 怎么用

- 面板打开「总开关」后，主人对她说「帮我截个屏」「把微信窗口切到前台」「读一下剪贴板」等，她会用 `windows_ops` 工具去做。
- 主人也可以在 QQ 里发 `/wops`：
  - `/wops ops` 看全部操作与风险等级
  - `/wops status` 看开关/待确认项/QQ 共享与协助状态
  - `/wops shot` 试一张全屏截图（图落在模块数据目录 `shots/`）
  - `/wops qq` 列出机器人/主人的 QQ 窗口（诊断窗口识别）
  - `/wops share` / `/wops share <QQ号或备注>` / `/wops share stop` / `/wops share status` 发起 / 停止 / 查看 QQ 原生屏幕共享（不带目标 = 主人；发起后先发截图，主人回复「确认」才真正点按钮）
  - `/wops assist` / `/wops assist <QQ号或备注>` / `/wops assist stop` / `/wops assist status` 发 / 取消 / 查看 QQ 原生远程协助邀请（不带目标 = 主人；同样先截图确认）
  - `/wops confirm 批准|拒绝 <尾号>` 批准/拒绝危险操作；如果正在等 QQ 发起前确认，也可 `/wops confirm 批准 <4位确认码>`
- 键鼠类操作（激活窗口/移动/点击/打字/按键，以及 uia.click / uia.setValue / uia.invoke）要再打开面板的「允许键鼠模拟」；
  **远程协助会把键鼠交给对方**，所以 `qq.assist` 也归为键鼠类，必须打开这个开关；屏幕共享只读屏幕，不需要。

## 窗口按机器人 QQ 号识别，不认昵称

QQ 窗口本身不显示 QQ 号，只显示昵称；昵称又会改。模块的稳定身份是 **QQ 号**：

- 机器人 QQ 号默认取插件配置里的 `botQQ`（面板也可以单独填）；
- 主人 QQ 号默认取 `ownerQQ`（面板也可以单独填）；
- **机器人窗口**：QQ 每个账号的数据分区在 `%APPDATA%\QQ\Partitions\qqnt_<QQ号>`，里面的 `DIPS-wal` / `SharedStorage-wal` 被该账号的 QQ 主进程锁着。模块用 Windows RestartManager 反查持有锁的 PID，再按 PID 锁定顶层窗口——与昵称无关，两个客户端同时登录也不会开错；
- **会话对象**：目标为空时，用 OneBot `get_login_info` / `get_stranger_info` 把主人 QQ 号解析成当前昵称；指定好友时，用好友表里的 `remark || nickname`。确认机器人窗口当前私聊就是目标，不是就点最近会话列表切过去；
- QQ 号这条路查不到（分区文件没生成、QQ 刚启动还没写盘）时，才退回「窗口自己的昵称 = 机器人昵称」、再退回「会话标题 = 目标昵称」；仍不行就在面板手填窗口句柄。`/wops qq` 可看当前窗口与 PID，方便核对。

## 按主人指令指定好友（v1.3.1）

默认目标就是主人；主人也可以让机器人把屏幕共享或远程协助邀请发给 **机器人 QQ 好友列表里的某个好友**：

- QQ 私聊：`/wops share 123456789`、`/wops share 同事小A`、`/wops assist 123456789`；
- AI 工具：`windows_share_screen` / `windows_remote_assist` 的 `target` 参数，填 QQ 号或备注/昵称。

解析规则：

- `target` 为空 → 主人（`ownerQQ` / `ownerName`）；
- 纯数字且 ≥5 位 → 按 QQ 号在 `get_friend_list` 返回的好友表里精确匹配；
- 其他 → 按 `remark` 或 `nickname` 精确匹配；重名时明确报错，要求改用 QQ 号；
- 排除机器人自己，以及「我的电脑 / 我的手机 / 我的Pad」三个设备伪好友；
- 选中后，机器人窗口里显示的会话名优先用好友备注（没有备注才用昵称），因为 QQ 会话列表显示的就是这个。

**找会话的顺序**：

1. 指定了 QQ 号时，先把 **QQ 号** 原样填进 QQ 左上角搜索框，等搜索结果里出现「来自: 我的好友」的人；
2. 按 QQ 号搜不到时，再用好友显示名（备注优先）搜一次；
3. 搜到后只点唯一一条 `search-result-item` 结果；最近会话列表（`recent-contact-item`）只作兜底，并且只认条目标题文本，避免同名消息预览误点；
4. 搜不到、结果重名、或结果不是好友，就明确失败，不会乱点陌生人或群。

搜索框路径依赖 QQ 当前版本的中文 UI（`搜索` 输入框 + `search-result-item`）；换 QQ 大版本后如果 UI 变了，模块会报「QQ 搜索都没找到」，不会假装成功。

## 发起前截图确认（v1.3.2，默认开）

`qq.share` / `qq.assist` 真正点 QQ 按钮之前，先加一道「主人确认」：

1. 模块先截当前屏幕（JPEG，落 `dataDir/shots`），通过 OneBot 发到 **主人私聊**；
2. 附一条文字：准备对谁、发起什么、确认码，以及「截图只发给主人核对，不会发给目标好友」；
3. 主人在 QQ 里回复 `确认`（或 `确认 <4位确认码>`）才真正执行；回复 `取消` / `放弃` / `不发` 则放弃；
4. 5 分钟没确认自动过期，不会发起；同一时间只允许一条待确认，避免「确认」放行错动作；
5. `qq.shareStop` / `qq.assistStop` 会先撤销同类型的待确认。

这不是恢复 v1.3.0 的「截图发帧当共享」：确认截图只用于发起前核对，真正共享仍然是 QQ 原生「屏幕共享」。面板「发起前截图确认」开关可以关闭；关闭后恢复直接点按钮。

开启时，主人的「确认」同时替代 `qq.assist` 的通用「危险操作确认队列」，避免一次远程协助要确认两遍；白名单、键鼠模拟开关、试运行、限速仍然照常校验。

**注意**：确认截图可能包含屏幕上的敏感内容，所以只发给主人私聊，不发给目标好友；发起前请先确认当前屏幕没有不该给别人看的东西。

## 屏幕共享（QQ 原生，机器人客户端）

主人说「给我看看屏幕」「用 QQ 屏幕共享」，她就用 `windows_share_screen` 发起（面板「QQ 屏幕共享」卡也能手动开）：

1. 先把当前屏幕截图发到主人私聊，等主人回复「确认」（见上一节）；
2. 确认机器人 QQ 当前会话是目标好友私聊（不是就点最近会话列表切过去；目标解析见上一节）；
3. Invoke 聊天工具栏的「屏幕共享」按钮；
4. 等 QQ 弹出「选择你想共享的窗口」，点「桌面」；
5. 等「确定」可点后点下去；
6. 用「停止共享」按钮确认共享已起来。

- **命令只由主人在私聊里发**，群里不发；目标可以是主人，也可以是机器人好友列表里被主人点名的人；总开关没开拒绝；
- 原生共享不会自己停，面板可设 **自动停止分钟数**（默认 30，0 = 不自动），到点调 `qq.shareStop`；
- 如果 QQ 的共享选择框一直转圈、「确定」始终灰的，模块会返回「共享选择框一直停在加载状态」的明确失败，不会假装成功；
  先在 QQ 里手动点一次「屏幕共享」确认这台机器能加载桌面源，再回来用模块。

## 远程协助（QQ 原生邀请，机器人客户端）

主人在面板打开「允许键鼠模拟」，然后：

- QQ 私聊发 `/wops assist`（或 `/wops assist <QQ号或备注>`，或说「邀请我远程协助」让她调 `windows_remote_assist`）；
- 她先把当前屏幕截图发到主人私聊，主人回复「确认」后，才在机器人客户端里点「远程协助」右侧箭头，再点菜单「邀请对方远程协助」；
- QQ 会话里出现「你正在邀请 <目标昵称> 控制你的电脑，请等待对方回应…」，对方在 QQ 里点接受即可直接操作；
- 取消：`/wops assist stop`，或对方在 QQ 里断开。模块会尝试点「停止协助/取消邀请」；找不到按钮时明确报错，不假装取消。
- 命令只由主人在私聊里发；目标可以是主人，也可以是机器人好友列表里被主人点名的人。远程协助会把键鼠交给目标，发之前确认对象没选错。

## 元素定位（UIA）：能用树就别用坐标

同样是点按钮、填输入框，有两种动法：

| 动法 | 操作 | 适用 | 弱点 |
| --- | --- | --- | --- |
| 坐标点击 | `mouse.move` / `mouse.click`（x、y 像素） | 什么界面都能点，Canvas/游戏/自绘界面只能靠它 | 窗口一挪、改大小、换主题/DPI 就全点偏；她不知道自己点到了什么 |
| 元素定位 | `uia.tree` / `uia.click` / `uia.setValue` / `uia.getText` / `uia.invoke`（pid + sel） | 普通程序的按钮、输入框、菜单、勾选框 | 界面不暴露无障碍树时读不到 |

默认优先元素定位（面板「元素定位（UIA）」卡的「优先用元素定位」开关，配置键 `preferUia`，默认 `true`）：
先 `uia.tree` 读树看界面 → 用选择器点名操作 → 实在读不到树才退回 `screenshot` + 坐标。

### 选择器语法（`sel` 参数）

格式「键=值」，多个条件用 `&&` 连起来（全部满足才算命中）。可用的键只有四个，
值按**前缀**匹配，不支持通配符：

| 键 | 含义 | 例 |
| --- | --- | --- |
| `AutomationId` | 程序给的唯一标识（最稳，优先用） | `AutomationId=submitBtn` |
| `Name` | 用户看得见的文字 | `Name=提交` |
| `ControlType` | 控件类型 | `ControlType=Button` / `Edit` / `MenuItem` |
| `ClassName` | Win32 类名 | `ClassName=Edit` |

```
AutomationId=submitBtn                    // 最稳：程序员给的唯一标识
Name=提交                                  // 用户看得见的文字
Name=提交&&ControlType=Button              // 多个条件一起钉死
ControlType=Edit&&AutomationId=username    // 输入框常见写法
```

每次操作都要带 `pid`（目标窗口进程号，先 `window.list` 认准）。元素**不跨调用有效**——
不要缓存元素，每次重新「pid + 选择器」去找；找不到元素时先读树核对字段名，别急着换坐标。

### 为什么填输入框要用 `uia.setValue`

`uia.setValue` 走 ValuePattern 直接把值写进控件，等价于程序内部赋值：**不受中文输入法影响**
（`key.text` 在中文输入法挂着时会把字母吃掉转成拼音，真机实测 `wops` 变成「我平时」）、
不用先点焦点、不受光标位置影响。而 `key.text` 只用短英文/数字，且作为 `setValue` 不被支持时的兜底。

## 指引体系（总纲常驻 + 手册按需，仿手机逛逛的分层设计）

- **主流程总纲 `main`**：经规则常驻注入（只挂主人私聊），总章程：怎么排任务、安全红线。第一原则是
  「动之前先观察——能读无障碍树就先读树，别盲点坐标」。面板独立一卡，只能编辑/还原，不能删。
- **单类手册**：`uia` 元素定位 / `input` 键鼠 / `window` 窗口 / `clipboard` 剪贴板 / `screenshot` 截屏 / `generic` 通用兜底；她按当前操作用 `windows_ops_guide` 工具现取（省 token），`uia.*` 操作自动取 `uia` 手册。面板「Windows 自动化指引」卡里像人格页那样分节编辑；自定义指引（`guides/<key>.md`，落数据目录）可覆盖内置、可删除（两道确认）。

## 安全

- 默认总开关关闭；工具只在**主人会话**放行（群友/别人不可用），`/wops` 命令本来就只认主人。
- QQ 共享/协助**命令只从主人私聊发起**：群里发命令一律拒绝；目标只能是主人，或机器人好友列表里被主人用 QQ 号/备注点名的好友，陌生人/群友/机器人自己都拒绝。
- 操作白名单：面板可挑操作加入，不在名单的一律拒绝（留空 = 按 builtin 规则放行）。
- 危险操作确认门槛：关窗口、键鼠动作（含 `qq.assist`）第一次执行只进确认队列
  （面板「危险确认队列」卡批准/拒绝，或 `/wops confirm 批准 <尾号>`），**一次性**放行（10 分钟内有效）。
- 试运行：只过闸门不真动，用来安全试配置；另有每分钟操作上限。
- 所有参数不直接拼进 PowerShell 命令行（经 base64 传给脚本内解码），SendKeys 按键只接受白名单键名；UIA 选择器在 JS 侧解析成 PropertyCondition，不进脚本拼串。
- 截图、日志、自定义指引写在本模块数据目录（`modules-data/windows-ops/` 下的 `shots/`、`logs/`、`guides/`），不写模块源码目录。

## 会访问哪里

- 平时不联网；本机执行 `System32\WindowsPowerShell\v1.0\powershell.exe`（路径可在面板改）。
- 不再监听任何端口：屏幕共享/远程协助都由 QQ 客户端自己走腾讯的通道，模块只通过 UI Automation 点 QQ 的按钮。
- QQ 客户端路径、账号数据都在本机；模块不读 QQ 账号数据库，只用 OneBot 查「QQ 号 → 当前昵称」和机器人好友列表（`get_friend_list`），用来核对目标是不是机器人好友。

## 能力声明

`filesystem`（写截图/日志/自定义指引到数据目录）、`process`（启动 powershell.exe、枚举 QQ.exe 窗口）、`plugin-internals`（用 `api.core.hub` / `api.core.http`、`api.onebot`）。
