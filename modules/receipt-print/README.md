# 热敏打印

把模板和提示词变成一张热敏小票。给模板写好提示词，接上打印机，就能手动触发或按时间自动生成并打印；她发空间说说时也会自动排版打印，配图按纸宽缩放，打完自动切纸。

## 它做什么

- **模板 + 提示词**：每个模板一条提示词，支持 `{date}` `{weekday}` `{time}` `{datetime}` `{width}` `{paper}` `{effective}` `{columns}` `{name}` `{moment}` 占位符。
- **生成方式**：`单问模型`（`api.ask`，快、不带人格）或 `让她想`（`api.think`，带人格和记忆，慢）。
- **五种触发方式**：手动、定时、启动时、她发完说说后、让模型判断。定时可设 `HH:MM` 和星期，同一天同一模板只触发一次；也可以随时发命令或点面板按钮。
- **默认模板**：首次启动会种下 8 个预设——「每日简报」「今日总结」「晨间计划」「今日菜单」「本周回顾」「睡前一句」「灵感便签」「说说随想」，全部自动触发：每日简报在启动时打，说说随想在她说说后跟打，灵感便签让模型判断，其余按时间（07:30 / 11:00 / 18:00 / 22:30 / 周日 20:00）。生成方式按内容分工：资讯、菜单这类固定格式用「单问模型」求快，计划、回顾、睡前、灵感、说说随想这类需要人格和记忆的用「让她想」。时间、触发方式、生成方式和开关都能改，模板可删，删了不会自己长回来。
- **每日彩蛋**：模板底部按日期随机出幸运数字、幸运色、今日关键词和一个 ASCII 小图案；同一天重打内容不变，可在设置里关掉。
- **纸宽自适应**：按毫米设置纸宽和有效打印宽度，自动换算每行列数，中文折行不会溢出。
- **一键自检**：面板按钮、`/自检` 或 `/打印机 自检`；默认发内置 ESC/POS 自检页，可替换成自己的十六进制指令。
- **真机校准**：打一张校准页，按毫米列出候选行，找出实际能完整打下的最宽一行，把数字填回「有效宽度」；末尾再打一个等宽方框，确认配图不会被切边。
- **全黑测试条**：打一条约 10cm 的实心黑，看打印头真正的出墨边界和断针；长度可调，最长 120mm，避免连续加热过热。
- **排版**：页眉、分隔线、页脚、二维码、走纸、半切/全切。
- **打印通道**：Windows 打印队列（USB）、网口 9100、macOS/Linux CUPS；没有打印机时用「只预览」。
- **单台打印机**：面板里填一台机器的名字、通道和纸宽，所有模板共用。
- **说说自动打印**：监听内置 `diary` 模块，她每次发空间说说后自动排版打印；配图按有效纸宽缩放成黑白位图，打完自动切纸。另可用「说说随想」模板在说说后跟打一张小纸条。
- **指令表与解码**：内置常用 Epson ESC/POS 指令表（约 70 条，可按名称/指令/类别检索），发送的指令流和打印机返回的状态字节都能翻译成中文；表外字节按十六进制原样列出。
- **状态读取**：网口 9100 直接回读实时状态；Windows USB 走驱动 Bidi/WMI 读离线、缺纸、卡纸、开盖、队列积压。USB 队列拿不到纸张将尽、切刀错误这类传感器细节。
- **打印备份**：每次出纸都在本机留一份备份，一次打印一个文件，记录正文、触发类型（命令/面板/定时/启动/说说/自触发/自检）、触发原因、打印机和结果；备份目录可粘贴自定义路径，`/小票 记录` 可回看。
- **错误主动汇报**：打印失败、自检失败或打印机返回脱机/缺纸/开盖/切刀错误时，主动私聊主人账号（10 分钟内同类错误不重复刷屏）；Windows 失败时会附上驱动状态。

## 安装

模块市场安装，或把 `modules/receipt-print/` 整个放进：

```text
<数据目录>/modules/receipt-print/
```

数据目录默认是 `~/.dsh/plugins-data/aurabot/`。模块数据、模板和打印记录在 `modules-data/receipt-print/`。

### 首次使用：先确认协议

安装后**必须先同意《热敏打印使用协议》**，否则所有打印、自检、校准、定时和说说自动打印都会被拒绝。

两种确认方式，任选一种：

- 面板顶部会显示协议全文，点「我已阅读并同意」；
- 聊天里发 `/小票 协议` 看全文，再发 `/小票 同意`。

确认记录保存在模块设置里（条款版本 + 时间）。条款有更新时会提升版本号并重新展示，需要重新确认，旧确认不会继续生效。

## 打印机怎么接

**建议优先用系统打印队列**：Windows 选「Windows 打印队列（USB）」，macOS / Linux 选 CUPS。队列由系统驱动负责传输和重试，兼容性最好，也不依赖打印机固定 IP；只有需要实时回读纸张、离线等状态时，才用网口 9100。

### Windows + USB（推荐，最常见）

1. 装打印机原厂驱动，在「设置 → 蓝牙和其他设备 → 打印机和扫描仪」里确认能打印测试页。
2. 记下打印机的**队列名**（就是列表里显示的名字，例如 `POS-58`、`XP-58`）。
3. 面板 →「打印机」→ 传输方式选 `Windows 打印队列（USB）`，目标填队列名。

模块通过 PowerShell 调 `winspool.drv` 的 `WritePrinter`，把 ESC/POS 原始字节直接写进队列，不经过驱动的文字渲染。要求驱动接受 RAW 数据（多数热敏机原厂驱动可以）。

### 网口 / WiFi

打印机设置里打开 RAW 打印或 9100 端口，面板里传输方式选 `网口 / WiFi（9100）`，目标填 `192.168.x.x`（端口默认 9100，也可以写 `IP:端口`）。

### macOS / Linux

先在 CUPS 里建好队列，传输方式选 `macOS / Linux CUPS`，目标填队列名。模块执行 `lp -d <队列> -o raw -`。

### 没有打印机

把面板里的传输方式设为 `只预览`，或干脆不配置。生成结果会作为文字回到聊天/面板。

## 设置

| 设置 | 说明 |
|---|---|
| 启用 | 关掉后定时不触发，命令会提示已关闭 |
| 纸宽（mm） | 常见 58 / 80，也可以填 40、110 等；默认 58 |
| 有效打印宽度（mm） | 纸的可用宽度，`0` = 自动（58→48mm，80→72mm）；每行字符数和末尾 `=` 分割线长度都由它换算 |
| 自检指令 | 十六进制，留空走内置 ESC/POS 自检页；填了就原样发送，不再发内置页 |
| 中文编码 | `GBK`（多数国产机）或 `UTF-8` |
| 切纸 | 半切 / 全切 / 不切 |
| 正文最大字数 | 模型输出超长会截断 |
| 打印页眉 | 模板名、日期时间、分隔线 |
| 每日彩蛋 | 默认开；模板底部加幸运数字、幸运色、关键词和小图案，同一天重打不变 |
| 出错私聊主人 | 默认开；打印/自检失败或打印机返回错误状态时私聊主人账号 |
| 备份目录 | 可直接粘贴绝对路径（如 `D:\小票备份`）；留空为 `modules-data/receipt-print/backups`，每次打印写一个 `receipt-*.txt` |
| 全局页脚 | 所有模板默认页脚，模板可覆盖；支持占位符 |
| 二维码来源 | 自动 / 只用固定内容 / 不打。自动：说说指向那条说说，消息链接指向该网页 |
| 二维码内容 | 固定文字或网址，支持占位符；留空且没有链接时不打 |
| 打印超时 | 默认 8 秒，连不上就报错，不阻塞聊天 |
| 说说自动打印 | 她发空间说说后自动排版打印，默认开 |
| 消息打印 | 消息里提到打印时先让模型判断是否真的要求出纸；默认只认主人，群聊要 @ 它 |
| 消息/网页最多打印字数 | 默认 1200，超长截断并标注「后略」 |
| 连仅自己可见的也说打印 | 默认关；`diary` 里 `visibility: self` 的条目不打 |
| 打印说说配图 | 默认开；配图按有效纸宽缩放 |
| 每条说说最多打印几张图 | 默认 3；`0` = 只打文字 |
| 图片最大高度（mm） | 默认 100；超高的图会整体缩小，避免一张图打太久 |
| 图片抖动 | 默认开，照片层次更自然；关掉是纯黑白阈值，适合文字截图 |
| 自动调色（色阶） | 默认开，自动拉开明暗，避免整张灰蒙蒙或糊成黑块 |
| 图片亮度 / 对比度 | 默认 0；热敏纸偏黑可调低亮度、调高对比度 |
| 图片伽马 | 默认 1.3，大于 1 提亮暗部（墨点会胀，稍提亮更耐看） |
| 图片锐化 | 默认开，文字截图和小图边缘更清楚 |

### 纸宽怎么换算

203dpi 热敏机是 8 dots/mm，Font A 一个半角字符 12 dots 宽：

```text
每行列数 = floor(有效宽度mm × 8 ÷ 12)
58mm 纸 → 48mm 有效 → 32 列（中文 16 字）
80mm 纸 → 72mm 有效 → 48 列（中文 24 字）
40mm 纸 → 30mm 有效 → 20 列（中文 10 字）
```

如果打出来右边留白太多或文字被切，就把「有效打印宽度」调大/调小，不用改代码。

每张小票末尾都会先空一行，再打一行按有效打印宽度铺满的 `=` 作为分割，然后走纸 6 行再切纸，保证最后一段内容完全送出切刀；改有效宽度后，这行等号也会跟着变长或变短，方便对齐撕纸。

### 一键自检

面板「打印机」里有「保存并自检」；命令是 `/自检` 或 `/打印机 自检`。

默认自检页由模块用 ESC/POS 生成，比 Windows 驱动自带的更全，依次是：

1. **设备信息**：打印机名、通道、目标、纸宽 / 有效宽度 / 列数、编码、抖动、自动色阶、锐化、亮度 / 对比度 / 伽马、切纸、超时、消息打印范围、说说自动打印、二维码来源、插件版本、打印时间
2. **系统信息**：用户名、计算机名、操作系统与版本、CPU 型号与核心数、CPU 主频、CPU 负载、系统内存（总量/空闲）、系统运行时长、启动时间、系统语言、时区、网络地址、用户目录、临时目录、进程 ID、进程内存、插件版本、Node 版本、V8 版本
3. **存储**：数据目录、磁盘总量、磁盘可用、磁盘已用百分比
4. **打印机信息**（Windows）：打印机名称、型号、端口名称、打印机处理器、数据格式、类型、共享/共享名、发布到目录、脱机、保留打印文档、位置、备注、状态、优先级、默认作业优先级、可用起止时间、队列作业数、每分钟页数、渲染器、属性、参数、允许用户管理
5. **打印配置**（Windows）：纸张大小、是否彩色、双面模式、打印质量、是否逐份
6. **驱动程序**（Windows）：厂商、驱动版本、环境、INF 文件、配置文件、数据文件、帮助文件、依赖文件（前 6 个逐个列出）
7. **端口**（Windows）：端口描述、主机地址、端口号、端口监视器、SNMP、LPR 队列、端口 URL
8. **环境打印机**（Windows）：系统打印机总数、默认打印机、前 8 个队列名
9. **插件信息**：插件版本与阶段、模板数量（定时/自动）、打印记录条数、协议版本、数据目录、备份目录、备份文件数量
10. **对齐测试**：分两段——「对齐指令」用 ESC/POS 居中/右对齐，「空格填充」用空格顶到中间和右边。两段都对说明驱动支持对齐指令；只有空格那段对，说明打印机忽略指令，以空格为准
11. **字号与效果**：常规、倍高、倍宽、倍宽倍高、加粗、下划线、反白
12. **缩进与版式**：四格缩进、居中、右对齐、左对齐
13. **字符测试**：中文、中文标点和全角、中英混排、长行折行、生僻字、繁体、日文，以及完整 ASCII 32–126 分三段打印
14. **数字与金额**：0-9、金额符号、日期时间、电话号码
15. **线条样式**：`-` `=` `.` `·` `~` 五种满行分隔线
16. **表格示例**：项目/数量/金额三列、虚线和右对齐合计
17. **条码测试**：CODE128 条码（打印机不支持时会空白）
18. **宽度刻度**：0-9 循环行 + 每 5 列一个 `+` 的刻度行，正好铺满整行；再加一个 ASCII 方框，左右边框被切一眼就看出来
19. **打印头测试图**：等于有效宽度的位图，6 段——1 点/2 点/8 点竖条查断针，斜向灰阶查浓度，棋盘查发热均匀，实心块查发热，最左最右各一条 1 点竖线
20. **走纸与切纸**：说明后走纸 6 行并按设置切纸
21. **自检二维码**：把这次质检的信息写进二维码（设备、系统、打印机型号/端口/处理器、驱动版本、时间和插件版本），手机扫一下就能复制留存。二维码至少用 4 点模块（58mm 纸约 0.5mm），长驱动路径只留文件名、重复字段省略，内容再多就截断，保证不超纸边、扫得出来
22. 「自检完成」，最后按设置走纸切纸

系统 / 驱动信息来自 `Get-Printer` / `Get-PrinterDriver` / `Get-PrinterPort` / `Get-PrintConfiguration` / `Win32_Printer`（只读，15 秒超时，读不到就跳过，不影响出纸）；非 Windows 只打系统、存储和插件信息。

每行都按显示宽度折行（中文算 2 列），所以不会溢出纸宽；刻度行正好到纸边，就说明有效宽度设置对了。

要发厂商自己的自检或特殊指令，在「设置 → 自检指令（十六进制）」里填，例如：

```text
1B 40 1B 61 01 48 65 6C 6C 6F 0A 1B 64 03 1D 56 42 00
```

支持 `1B 40`、`0x1B,0x40`、`1B401B61` 三种写法。填了之后自检会原样发送这段字节（不再追加模块生成的内容），所以切纸、走纸也要自己写进去。

### 真机校准

面板「打印机」里点「打印校准页」，或发 `/小票 校准`、`/打印机 校准`。

1. 纸上会按 2mm 递减打印 `48mm ####...]` 这样的行，毫米数在最前面，末尾 `]` 在同一行说明这一行没超宽，每行按 12 点字符估算宽度。
2. 找**末尾 `]` 还在同一行**、且没有换行的最长一条，它开头的毫米数就是这台机器实际能打的宽度。
3. 把数字填到「有效打印宽度」（也可以填在打印机自己的纸宽里），保存后再打一张确认。
4. 校准页末尾有一个等于当前有效宽度的空心方框；右边框完整没被切，说明图片宽度也合适。

末尾 `]` 掉到下一行、或者不见了，都说明那一行超宽。校准页和其它打印一样会留备份、自动切纸。

### 全黑测试条

发 `/小票 黑条` 或 `/打印机 黑条`，会按当前纸宽打一条 100mm 长的实心黑。想改长度就在后面带毫米数：

```text
/小票 黑条 80
/打印机 黑条 120
```

- 黑色左右边缘就是打印头实际能出墨的范围，边缘有白缝、断线，说明那一列针有问题或纸宽设置偏大。
- 长度限制 20–120mm，默认 100mm；全黑连续加热很吃打印头，不建议超过 120mm，也不要连续打很多张。
- 宽度按「纸宽」换算（58mm → 464 点），会比有效宽度更宽，这样黑色边界停在哪里，就是打印头真正的出墨范围。

### 占位符

模板提示词、系统提示词、页脚、二维码内容里都能写占位符，打印时按当前时间/纸宽替换；不认识的 `{xxx}` 原样保留，模板标题不替换。

| 占位符 | 输出 | 例子 |
|---|---|---|
| `{date}` | 日期 | `2026-11-27` |
| `{time}` | 时分 | `09:05` |
| `{datetime}` | 日期 + 时间 | `2026-11-27 09:05` |
| `{weekday}` | 中文星期 | `星期五` |
| `{weekdayNum}` | 星期数字，0 = 周日 | `5` |
| `{width}` | 每行字符数 | `32` |
| `{columns}` | 每行字符数（同 `width`） | `32` |
| `{paper}` | 纸张宽度 mm | `58` |
| `{effective}` | 有效打印宽度 mm | `48` |
| `{name}` | 当前模板名 | `每日简报` |
| `{moment}` | 触发这次打印的说说正文（仅说说后自动打印时有内容） | `今天风很大` |

例：页脚写 `{date} {time} · {name}`，打印出来就是 `2026-11-27 09:05 · 每日简报`。对话里发 `/占位符`（或 `/手册`）随时查这张表。

### 二维码

「二维码来源」有三种：

| 来源 | 行为 |
|---|---|
| 自动（默认） | 说说 → 这条说说的网址；消息/网页打印 → 消息里的链接；没有链接才用「二维码内容」 |
| 只用下面的内容 | 永远打「二维码内容」，适合固定 WiFi、店铺主页、联系方式 |
| 不打二维码 | 整张纸都不出二维码 |

「二维码内容」可以写文字（`AURABOT · {date}`）也可以写网址（`https://example.com`），支持占位符；模板自己的二维码设置优先于全局。

### 消息打印

**消息里出现「打印」不会立刻出纸**：模块先本地筛一遍，再让模型判断这句话是不是真的在要求打印。普通聊天、问打印机状态、开玩笑提到打印都不会打；只有模型确认后才排版出纸。

- `打印 今天开会的内容` → 去掉「打印」两个字，把后面的正文打出来
- `帮我打印 https://example.com/article` → 抓网页正文打印
- `打印` + 图片 → 打图片，不会把「打印」当成正文
- `把这段文字打印出来` → 打「这段文字」里的内容（指代本身不打）
- `能不能把这句话打印出来` → 模型确认后一样打，指令词不会进正文

支持的说法有「打印」「帮我打印」「打出来」「打一张」「打一下」「打成小票」「印出来」「出小票」等；以「别打印」「不要打印」开头的不处理。模型不可用时会退回严格规则：明确命令照打，模糊提及不打。去掉指令词后只剩「这个 / 这张图 / 图片」这类指代时，当没有正文。

- **文字**：整段按纸宽折行，走纸切纸
- **图片**：最多 9 张，按有效纸宽缩放再转黑白位图；图片和文字一起发时先打文字再打图
- **链接**：消息里第一个 `http(s)` 链接会被抓下来，优先取 `<article>` / `<main>` 正文，去掉脚本样式，标题放开头，超过「消息/网页最多打印字数」就截断

主人以外的人发消息默认不响应；「消息打印」设成「所有人」才放开，群聊任何时候都要 @ 它。以 `/` 开头的内容不接管，交给命令系统。

### 说说自动打印

模块每 30 秒读一次内置 `diary` 模块的 `history()`：

1. 只处理比上次水位更新的说说；第一次启动只记下当前位置，不会把历史说说全打一遍。
2. 默认跳过 `visibility: self`（仅自己可见）的条目；打开「连仅自己可见的也说打印」才打。
3. 正文按小票纸宽折行，页眉显示「说说」和发布时间，页脚跟全局设置走；二维码在「自动」模式下指向这条说说自己的网址（`https://user.qzone.qq.com/<QQ>/mood/<tid>`，宿主给了 `url` 就直接用），拼不出网址时退回固定内容。
4. 配图从 `images` / `pics` / `photos` / `media` 字段，或正文里的 Markdown 图片、图片直链里取；单张最大 8MB，只支持 JPEG / PNG。
5. 图片铺满有效纸宽（58mm 纸 = 384 dots），太高会等比缩到「图片最大高度」；缩完先自动色阶，再按设置做亮度/对比度/伽马和锐化，最后抖动或阈值成 ESC/POS `GS v 0` 光栅位图。热敏纸只有黑点，调色比单纯缩放更影响可读性。
6. 一张小票的正文和图片都发完，统一走纸并按「切纸」设置半切/全切。

如果宿主版本的 `diary` 没有暴露 `history()`，或者历史里不带图片字段，模块会静默跳过/只打文字，不会影响其他功能。

没自动打印时先发 `/打印机 说说` 看诊断：它会列出开关、`diary` 模块是否可用、读到几条、已打印到哪一刻、待打几条，以及有多少条「仅自己可见」被跳过；`/打印机 补打` 会立刻检查并补打一次。

## 模板字段

面板里编辑：

- **名称**：也是 `/小票 名称` 的引用名。
- **提示词**：发给模型的正文，支持占位符。
- **系统提示词**：可空，默认要求纯文本、不要 Markdown。
- **生成方式**：`单问模型` 或 `让她想`。
- **触发方式**：手动 / 定时 / 启动时 / 她发完说说后 / 让模型判断。
- **纸张**：跟随打印机，或强制 58 / 80mm。
- **页脚 / 二维码**：可空，支持占位符。

### 五种触发方式

| 触发方式 | 什么时候出纸 | 说明 |
|---|---|---|
| 手动 | 发 `/小票 名称` 或点面板按钮 | 默认只在你要的时候打 |
| 定时 | 每天（或指定星期）的 `HH:MM` | 同一分钟只触发一次，同一天同一模板只打一张；机器人要在那个时间点运行，不补跑 |
| 启动时 | 模块加载后的第一个检查周期（约 1 分钟） | 每天最多一次，机器人重启不会重复打 |
| 她发完说说后 | 检测到新说说时，紧跟说说小票再打一张 | 同一批说说只跟打一次；提示词可以用 `{moment}` 拿到说说正文 |
| 让模型判断 | 白天每 3 小时问一次模型「现在要不要打」 | 只有模型回答「打」才出纸，23:00–07:00 不打，每天最多 3 张 |

「说说随想」是唯一带 `{moment}` 的预设，模型能看到她刚发的说说再写感想；不想每次说说都多一张，可以把它改成手动或删掉。

定时判定是「当前分钟等于设定时间」，所以机器人需要在那个时间点运行。补跑不会自动发生，避免重复出纸。

## 数据与隐私

- 模板、打印记录、`lastRun` 都存在 `modules-data/receipt-print/state.json`。
- 打印记录只存模板名、打印机、成功/失败、字数，不存生成正文。
- 生成走 `api.ask` / `api.think`，和插件其他模型调用一样。

## 已知限制

- Windows USB 通道依赖 `winspool.drv` 和原厂驱动，代码在 Linux 上只做了命令构造测试，**没有在真机 Windows 上验证**；第一次用请先打自检页。
- Windows USB 的状态来自驱动 Bidi/WMI，能读到离线、缺纸、卡纸、开盖和队列积压，但读不到「纸张将尽」「切刀错误」这类传感器细节，也可能滞后几秒；要实时状态得走网口 9100 或串口。
- 自检的列数按 203dpi / 12 dots 字符宽计算；如果你的机器是 300dpi 或换过字体，用「有效打印宽度」微调即可。
- 图片只支持 JPEG / PNG，不处理 EXIF 方向；手机竖拍照片如果打出来是横的，先转正再发。
- 打印机离线时会在超时后报错，不会自动重试排队。
- 需要 Node 22+。

## 开发

```sh
cd modules/receipt-print
npm ci            # 必须先装依赖，否则测试无法运行
npm test          # 布局、字节、模板、传输、存储、图片、说说
npm run build     # 产出 .build/
```

测试依赖 `npm ci` 安装的 `node_modules`（`iconv-lite`、`jpeg-js`、`pngjs`）。没装依赖直接跑测试，涉及编码、图片和模块入口的 4 个测试文件会报 `ERR_MODULE_NOT_FOUND`，这是缺依赖不是用例失败。CI 请先在本目录执行 `npm ci`（或 `npm install`）再跑 `npm test`。

仓库根目录的 `node scripts/check.mjs` 只做静态检查（模块清单、capabilities、构建产物），不需要 `node_modules`，可以直接在任何干净 checkout 里跑。

测试不依赖真打印机：网口用本地假 TCP 服务器，Windows/CUPS 用注入的 spawn 断言命令参数。
