# 宝可梦对决（duel）

群里喊一声，两条鱼当着两个主人的面打一场回合制嘴炮。主人下口令，鱼照着演，你来我往几个回合，最后一条鱼当裁判判个输赢。

只是**娱乐友谊赛**，不动真格，也不代表任何真实对抗。属性克制、招式、技能全都只影响描述，不改数值。

## 怎么玩

两个人都装了本模块、都在同一个群里：

1. 甲主人：`发起决斗`
2. 乙主人：`接受`
3. 甲主人的鱼连发两条系统提示，把回合推进起来
4. 上半场：甲主人下令（`第一回合，用水枪喷它`）→ 甲的鱼反应 → 乙的鱼反应
5. 下半场：乙主人下令 → 乙的鱼反应 → 甲的鱼反应，然后甲主人的鱼开下一回合
6. 打满设定回合数后，甲主人的鱼当裁判：`对决结束，某某获胜`

每回合大概 6 条消息（两个口令、四条反应），外加一条推进用的系统提示。默认 5 回合，约 20 次模型调用加一次判胜。

随时可以 `对决` 或 `/duel` 看当前状态。

**两边都要装这个模块**：它没有服务端，靠两条鱼各自在群里广播「该谁了」来同步回合。只有一边装是打不起来的。

## 设置

面板「扩展」页里这个模块的卡片：

| 设置 | 说明 |
| --- | --- |
| 等待接受超时（秒） | 喊了「发起决斗」以后等多久没人应就取消，默认 120 |
| 每回合超时（秒） | 等主人下令、等对方鱼反应的时间，默认 180；超时这一方算输 |
| 回合数 | 默认 5，最多 10 |
| 谁能应战（主人 QQ） | 只有名单里的主人说「接受」才算数，逗号/空格/换行分隔；留空表示谁先喊都行 |
| 鱼的信息 · 属性 / 技能 / 特性 / 其他 | 给模型当表演参考（惯用属性、招牌招式、性格毛病）。留空就是没有，**不加也不减实力** |

鱼的信息只写进提示词，代码不解析、不查表、不算伤害，输赢仍然看场面和嘴皮子。

## 对决期间群里发生什么

- 开了对决的那个群，所有消息都会被这个模块接管，不再进她的大模型对话，也不会插嘴——这是故意的，免得到时候她一边打一边闲聊。
- 别的群不受影响。
- 反应由 `api.ask` 单独生成，不带聊天历史，也不写进会话。

## 会用到哪些能力

`module.json` 里声明了两项，代码里实际只用这两样：

- `plugin-config` —— 读本模块的设置项（`api.config()` 取自己的 QQ，用来过滤自己发的消息）。
- `plugin-internals` —— 读当前人格正文（`api.core.personas.current()`，让鱼说话的腔调跟着她走），以及发送前用 `api.core.hub.cleanOutbound` 探一次这条反应会不会被出口清洗整条删掉。

不联网、不读写本机文件、不启动程序、不动态执行代码。生成文本交给宿主现有的模型调用，模块自己不连任何服务器；聊天内容除了本机的模型接口，不去别的地方。

## 两个坑，已经绕开

- **外壳不能用【】**：宿主的出口清洗会把 `【系统……】` 开头的整段当成注入的提示词删掉（`reply.js` 的 `memoryPromptRanges`），用它发的回合提示在群里其实什么都看不到，只剩一条「整段都是提示词复读」告警。所以协议外壳用 `〈系统提示：…〉`，并且仍然能认旧版的 `【系统提示：…】`。
- **对方鱼必须认同一套协议**：两个版本差太远（比如一边 0.x 一边 1.x 改了协议）会互相听不懂，表现为一方一直在等、另一边没动静。升级时两边一起升。

## 已知限制

- 同时只能在一个群开一场（模块里的对战状态是单份的）。
- 只支持群聊，私聊里不生效。
- 模型输出仍然是提示词约束，偶尔会跑偏（比如该写动作的时候只写了台词）；跑偏了不影响回合推进。
- 判胜是让模型看记录挑一个名字，挑不出来时默认发起方获胜。
